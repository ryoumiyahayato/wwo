## Godot 读取与画面

`GeographyLoader` 在 `MapJobs` 中按视口请求独立页。每页解码原 RGBA8 和全部离线 mip。页的 bounds、真实源精度、透明覆盖边及 mip 字节保留。每页仍作为一张现有纹理按帧预算提交，换区沿用原退役策略。源工程可用 `--compact-map`，可用 `--legacy-map` 复查旧地貌。单页 PCK 实测通过正式解码入口恢复原 mip。同一英吉利海峡战略分片在有／无预编译显示两条路径都返回岸线和陆地拾取数据。

Windows Godot 4.6.3 Compatibility，RTX 3050 Laptop。对德国 2°、中欧 8°／16°、北美、南亚和东南亚六页各读五次。每种模式从新 Godot 进程开始。冷指进程内首次读该页，未清空 Windows 文件缓存。热为其后四次，纹理每次释放重载。下表为中位数，单位 ms。

普通 1280 × 720 正式菜单新开局，暂停世界。在紧凑路线实际安装 15 个不同 WWOCM2 页，记录 47 次解码。两张 16° 纹理的 GPU 回读含全部 mip，与原文件逐字节相等。五组截图的全屏 RGB 差异占 0.15%–0.43%。地图中央裁剪中，WORLD、撒哈拉和采尔马特相同，阿尔卑斯和平原分别有 254 和 903 像素不同。整帧没有达到逐像素相等。两条路线均触发同一个 235,118,304 B 战略绘制预算错误，且采尔马特 LOCAL 网格未安装。完整路线未通过。正式存档未参与。

## 固定生产约束

1. 同一源对象和有序坐标只存一份。粗细层只保留无法从该源精确重建的增量。水体、岸线、边界和拾取保留独立语义。能证明同样性的显示数据，按视窗重建并按原预算提交。
2. 地貌按实际准入范围和源精度编目录。每个空间页一次发布、按需解码。阴影和地类重复通道应改成共享高程、支持掩膜和确定性派生，并先以原效果和边缘回读确认。已有全 mip 比对流程继续用于编码变更。离线原始资料留档，必需运行资产随安装交付。
3. 城镇地表优先试精确索引、色板和共享矢量环。遮罩只承担原有显示精度内可等价表达的内部覆盖。保留河口、港池、地类交界和矢量拾取边，混合层与三角网格对照后才替换。跨区城镇和瓦片按已有 ID 与同一覆盖窗口共享。楼廓多档、建筑实例和地标模型应避免按行政区重复封装。
4. 城镇地表 257 MB、已有楼廓遮罩与细页是下一批成本重点。战略图先共享同源拓扑弧，再按请求重建非拾取三角面和组件 UV；保留近景加载预算及离线回退源。若不改造这些类别，只重编码现有容器仍会超标。
5. 用唯一安装 PCK 条目计量每批的净增量，同时保留旧预览独立回退。3 GB 上限下，当前包约剩 0.77 GB；低情景新增 1.15 GB，仍差约 0.38 GB。需从现有底座和后续生产同时释放这部分。地貌页、城镇窗、岸段和 LOCAL 按地区统计实际字节后，才能承诺 2.x GB。

R68 通过 [版本化地貌配方](../../tools/build/r68-relief.json) 从独立保存的 R67 EXE 复原 287 张 WWOCM2 页及其余已验证的 FRA0 页。旧战略载荷备份在 `local-artifacts/map-task-a/original`。

## 欧陆地表共享索引

Godot 离线转换对 `europe_context` 全部 2,087 张 z8/z10 地表逐张比较原 `ArrayMesh` 的完整数组。新布局分列保存无损经纬度位差，按三角面保存相对索引，并共享每张瓦片内的色板。坐标、地类色值、三角面顺序和拓扑相同。地表沿用现有显示与拾取入口，楼廓遮罩保留现有表示。真实来源精度与已有瓦片范围未扩大。瓦片内覆盖遮罩与精确矢量边混合仍待验证。

地貌 R57 的 RGB 来自按范围采样的地类色及阴影，alpha 是独立的中性 DEM 亮度。不同 LOD 有各自采样及平均规则。仅从现有 RGBA 无法恢复原高程与地类。下一批应从共同源格网生成坡度和色层，对各 LOD 记录必要的边界与取整残差。战略 `.geom` 继续使用已验证的同源坐标别名；岸线、边界与跨 LOD 拓扑共用弧线的容量收益未知，本轮按零收益计入。
