# WWO 紧凑地图接入与迁移方案

## 当前决定

正式宿主继续使用 Godot 4.6.3 Compatibility。第六阶段接入一套可选的 WWOCM2 基础资源包。地图、经济、人口、人物、政治、军事、存档和 UI 沿用正式入口与组件。该版本用现有 MapJobs 调度与地图提交预算运行。

R67 已导出程序约 2,241 MiB，其中地貌、城镇和战略地图约占 85%。第一阶段两次代表性地图卡顿中，暂停世界时钟后地图 CPU 准备与提交仍耗时约 79 ms 和 42 ms。第三阶段限制读取、CPU 准备、GPU 上传和退役，第四阶段同机对照支持本机默认两个并发任务。第四阶段的巴黎剩余长帧包含约 249 ms 的地标与城镇场景更新。本阶段把城镇显示索引解析移到现有地图工作队列，索引随显示层释放。地图在细节等待期间使用现有粗层。

第五阶段的独立样机在同一台 RTX 3050 Laptop 上均约 60 FPS。Rust＋wgpu 把巴黎资源就绪从 383–400 ms 降至 33–34 ms，程序从 99.83 MiB 降至 5.35 MiB。它的 P99 为 17.41–17.43 ms，Godot 为 16.88–16.89 ms。Rust 的专用显存采样峰值为 106 MiB，Godot 为 71 MiB。独立样机省下的 CPU 和程序空间尚不足以承担正式地图交互、界面、地形训练和平台发布的集成维护成本。

## 所有权与资源契约

- 正式世界保持一份 **WorldState** 和 **GameClock**。**SimulationStep** 按现有阶段提交权威状态。经济账本、对象 ID、待办事件和政治军事引用继续使用原组件。地图工作线程持有显示输入，旧镜头结果按请求代次丢弃。
- WWOCM2 保存跨引擎共享的数据和空间索引。8 字节魔数后是小端 u32 索引长度、UTF-8 JSON 索引及块数据。块偏移相对数据区起点。光栅条目记录级别、起点、宽高、编码和原数据类型。正式地理目录仍负责来源与覆盖范围。首批包只为已有来源路径选择不同的物理存储。
- 边界、河网连接、道路、城镇位置和对象 ID 随来源保留。政治颜色、渲染网格、阴影和 LOD 属于显示数据。生成的 mip 采用逐字节相等的整数盒式规则。参与计算的高度使用原始 Float32 精度。光栅读取器当前按块读取并拼装既有整页纹理，最终上传字节数与原页相同。
- 城镇索引在现有工作队列中按需解析，地区切换时随拥有者释放。城镇网格仍使用原加载路径。Ridgevale 训练使用观察地形工作任务已验证的 4 米高程，原生碰撞和采样共享该数组。现有训练入口、战术规则和存档隔离保留。

## 首批资源与回退

基础包位于 [assets/maps/compact](../../assets/maps/compact)。它包含源路径清单和两份第二阶段产生的原始 WCM 文件。磁盘对照按替换的文件集合计量。

| 资源 | 旧文件字节 | 紧凑文件字节 |
| --- | ---: | ---: |
| 阿尔卑斯地貌和 mip | 3,367,913 | 3,310,723 |
| Ridgevale 4 米高程 | 6,260,004 | 3,405,752 |
| 包清单 | 0 | 237 |
| 合计 | 9,627,917 | 6,716,712 |

这两项减少 2,911,205 字节，约 30.24%。源目录并存时，工作区增加 6,716,712 字节。正式安装包字节数需在后续授权导出后测量。当前 Windows 导出预设和旧资产保留。

从正式菜单启动源码时，加上参数以试用该包。

    Godot_v4.6.3-stable_win64.exe --path D:/programs/WWO/wwo -- --compact-map

随目录交付时可用 --compact-map-pack 指定包含 base.json 的目录。缺失或无法解码的候选资源回到原读取路径。回退同一源码时，退出游戏后去掉 --compact-map 或加 --legacy-map，再从正式菜单载入原存档。现有 v15 快照和 exact Variant 外层格式继续使用。

退回已安装的 R67 时，使用原 R67 可执行文件和本次试用前由该版本保存的存档副本。本阶段的存档兼容检查覆盖同一源码的两种数据模式。跨版本读档取决于旧程序本身的快照与校验契约。

i7-13700H、RTX 3050 Laptop、1280×720，Godot 4.6.3 Compatibility。两种模式各运行三次，同一正式菜单开局和镜头路线，覆盖复杂海岸、巴黎缩放、阿尔卑斯、训练进出、跨区跳转与静止。对照期间暂停世界时钟，存档检查另推进一小时。表内依次为最小–最大 / 中位数 / 均值。

地图段超过 100 ms 的帧合计从 4 帧降为 1 帧。六轮的巴黎近景均就绪，采样时各有 30 个城镇缓存资源。候选私有内存峰值中位数少 102 MiB。专用显存范围重叠。候选训练就绪中位数慢约 160 ms，训练仍出现约 1.08–1.09 秒的长帧。

已逐字节核对阿尔卑斯 RGBA8 全 mip 和 Ridgevale 高度数组。候选模式推进 60 游戏分钟后保存，退出进程后经正式菜单以旧模式载入，时钟、玩家状态含 ID 和账本快照一致。候选目录缺失时，两项资源均回到旧读取路径。Ridgevale 的独立原生入口仍读取原始高度文件，未来发行排除旧载荷前须处理该依赖。新 Windows 正式安装包体积、R67 载入此次新存档和 Android 均为 NOT_RUN。

## 渐进迁移

1. 扩展已证实无损的地貌分片。以现有地貌目录为来源，按视口选择、保留可用的低精度层，按预算提交与回收。评估全包减重和连续换页后的内存平台。旧资源在独立回退版本中保留。
2. 将 WWOCM2 的海岸索引接入正式战略图层，按需读块。验收点是完整岸线、政治边界、河道连通与原有拾取。巴黎当前保留 Godot 网格。第二阶段该候选在 Godot 的读取 P95 为 145.47 ms，旧网格为 13.15 ms。后续先处理显示索引和可见块解码，再按实际重复的建筑几何与材质建立实例复用。
3. 用现有 [性能预算](../PERFORMANCE_BUDGET.md) 在正式世界路线复测。Windows 1280×720 的现有目标为平均至少 30 FPS，持续交互避免频繁超过 100 ms 的停顿。只有同等正式交互、画面与资源负载下仍存在明确热点，才比较独立原生解码或地图运行时，实测接入和后续维护成本。Android 另行在设备上测量。
4. 若将来需要更换宿主，先通过原存档读取器在副本上导出有版本的中立快照。保留整数金额、稳定 ID、唯一时钟、事件及结算顺序、待处理队列和关系引用。旧存档保持可恢复。对比相同输入下分阶段提交和存档往返，再切换唯一世界写入者。原军事训练需保留独立会话、物理支撑和控制路径。
