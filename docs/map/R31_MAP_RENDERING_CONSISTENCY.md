# WWO R31 — Map Rendering and Loading Consistency Fix

日期：2026-10-16。基线：本机R29及主菜单加载修复。Godot 4.6.3 Compatibility。

本轮修改公共加载、分片选择、安装与边界显示代码。没有启动游戏、采集截图、运行测试、回归、性能采样、哈希核验或Git操作。下文区分代码中确定的问题与尚未确认的截图归因。

## 1. 首屏为何只有国界，等待后才出现陆地和旗帜

`FormalWorldMenu._install_preview()`原来在历史国家、CPU历史拾取几何及Renderer初始化完成后，立即设`_preview_ready=true`并隐藏加载画面。

此时独立物理资源尚未通过另一条异步链路完成：

`GlobeRenderer._sync_strategic_resources()` → `StrategicSpatialLoader._load()`读取当前范围的JSON、geom和政治ink → `LocalSpatialLod.prepare()`准备同LOD的面与线 → `LocalSpatialLayer.prepare_step()`分预算上传 → Renderer提交相机、政治样式和视口更新。

历史国界批次比这条链路更早存在。原完成条件没有检查后者，能确定会提前开放仅有边界的地球。旗帜本身由既有`PoliticalLayer.visual_textures`保存；独立陆地绘制批次安装后才绑定对应纹理，不能把晚显示一律称为PNG读取慢。

现在菜单初始化后进入“当前视野显示安装”阶段。`GlobeRenderer.current_view_map_status()`检查实际请求、Content对象、目标LOD、当前政治几何、上传错误及地图提交标记。菜单只在返回`installed`后解除遮罩。实际消息区分读取分片、安装陆地/海岸/着色、提交显示。

这是资源安装及提交条件，不是GPU截图验收或驱动栅栏。不等待`RenderingServer.frame_post_draw`，也不等待全部456片、354份ink、LOCAL模型、经济或军事结算。保留必需资料失败、错误显示、手动重试、返回菜单和过期请求丢弃。显示检查自身中断也有下一次UI处理的失败出口。仍在合法运行的线程不会因等待时间而被判成成功或强杀。

## 2. 矩形缺块与非洲暂时缺失：确认了什么

发现以下公共路径问题：

- **WORLD漏选风险**：旧请求用`mpp × 屏幕半对角线`近似球面半径，再截为9000公里。WORLD是正交球面投影，屏幕半径对应弦，地表角距应取`asin(屏幕距离/球半径)`。可见半球到地平线约10007.6公里。尤其在8500米/像素以下退出“全部粗片”分支时，原半径可能漏掉仍可见的边缘片。新请求按实际球面角距选择当前粗/中片，不再截成9000公里，也不再让远WORLD无条件读取全部24个粗片。
- **REGION锚点偏移**：选择中心来自`valid_anchor()`，旧半径及批次剔除却假定中心始终在画面中央。平移到有限投影范围边缘时，两者可不一致。现在请求与批次剔除均按有效锚点到四角的最大距离计算，保留原8像素显示余量，没有移动地理顶点或扩大海岸缓冲。
- **失败抹除旧图**：Renderer遇到物理读取失败会清空已经有效的整层。现在保留已安装批次，并通过现有地图反馈报告错误。没有将失败Content安装为新图。
- **上传失败仍完成**：原安装循环对空纹理或无Mesh surface直接`continue`，最后仍标记LOD完成并退休旧图。现在失败即停止本次安装，清理未完成批次并保留上一完整显示，不发布“少了几批”的成功结果。
- **快速后继请求可能丢掉刚完成批次**：`begin()`只按上一次draw留下的`active_lod`选回退；新LOD刚上传完成而尚未draw时，该字段可能仍指向已退休的旧LOD。现在优先选择已完成的目标LOD，再选择上次活动LOD。

分片本身是矩形打包范围。漏选某片或错误发布少批次的结果，会把缺失边缘暴露成直线切口。这是可以从代码确认的形成路径，但不能据此认定截图中的每一块矩形、非洲全部缺失都只有同一原因。本轮未重现场景，仍需用户查看新预览。

## 3. 政治分区是否漏掉物理陆地

直接读取两份已有衍生资源：欧洲`physical_2_4_mid_0_1`及非洲`physical_2_3_mid_1_0`。其政治三角形联合范围与物理P的面积分别约108.971153和150平方度；差集只有约十亿分之几平方度的坐标精度余量，没有发现能解释大面积矩形空缺的漏分区。

这只是两个问题区域样本的资源内容检查，不是全456片验收，也不证明所有资源都没有错误。没有重新生成或修改任何geom、ink或原始GIS。

仍沿用R27单次物理填充：有ink时用同一P内的完整政治分区，没有ink描述时用原P。没有归属或当前样式的分区继续采用中性物理色，不将陆地删成海。没有同时增加一套完整政治陆地。

加载器新增ink的LOD与物理描述一致性检查；错误文件不能以另一精度安装。CPU准备也检查实际内容是否有目标物理LOD。没有每次加载重做全世界布尔运算。

## 4. 填充、海岸、政治状态怎样安装与切换

继续使用原Content线程、LOD线程、2000微秒上传预算、隐藏暂存批次和完整旧LOD保留机制。不是新建加载器。

物理陆地、同源海岸及政治分区使用同一个成功请求与LOD。移除上传循环中的中途完成入口；全部暂存上传完成后才统一发布目标LOD、物理水域引用与已安装政治几何，再退休旧批次。R28的受影响政治分区替换继续只替换相关陆地批次，海岸和DEM不参与重新制作。

新增线程启动错误码、返回类型、字段、LOD和批次结构处理。浮点退化面在原编码过滤后若整批为空，在CPU阶段省略；真正上传失败不再与这类合法空结果混淆。安装脚本中断可在下一处理步转为明确失败。

另外区分了所选物理片与区域补充包。物理陆地/海岸/必要ink失败仍是本次显示失败；区域聚落、铁路及河流补充包若读取失败，原线程记录其具体错误，不安装该包的部分内容，其他完整物理内容可以继续完成。复用同一读取函数，先取补充包的有效features，再统一制作一次线批次，没有增加线程、加载器或第二份几何缓存。菜单使用原状态文字说明哪些可选图层未加载，正式地图使用原反馈入口；没有把缺少必要陆地说成成功。

读取/准备失败保留旧的有效显示。相机仍用当前坐标投影这些地理批次，不冻结旧屏幕图片冒充新位置。新范围准备时使用现有地图反馈提示。旧内容不能覆盖的新范围仍要等待资源，不能保证任意高速连续移动都无需等待。

## 5. 德国粗折线、重复边界与行政错位

确认细国界安装完成后，`_install_overlay_chunk()`原先只`queue_redraw()`并请求视口更新，未设`_map_canvas_dirty`。关闭粗国界的`_draw_boundaries()`位于地图内容提交分支，因此新细线已经可见时，旧粗线可能继续保留在缓存目标上。现在使用原`_invalidate_appearance()`触发该分支，使粗细版本按原完整替代条件交接。没有删除历史边界。

共享历史国界来自`data/presentation/political_border_display_r3.json`，细线来自其`detail_path`。德国`gw_255`相关记录为046、049、050、055、059、061、062、063、064。该文件说明WORLD为1500米概化、REGION细线为80米显示参考。已读取这些记录；不能仅凭“德国附近”断言截图具体是其中哪一条，还是行政线或控制线。

共享国界入口改用既有`GlobeProjection.display_line()`，与物理面采用同一球面边缘细分约定，不改变原端点。R25的行政源投影采样`_projected_overlay_segment()`仍保留：细档每2公里、其他档每12公里沿原源投影线取样，再转换到球面。外环、孔与组件继续分别处理，不将组件首尾连成一线。

历史粗边界与动态/行政叠加线在首批物理内容完成前不再单独露出。当前主权、实际控制和历史行政仍各读原正式来源；新细边界完成时的重复显示已修正。没有移动行政GIS以贴合现代海岸。

**德国截图中粗长折线的唯一原始记录仍未确认。** 重复粗细线的公共错误已经修正；不能把这个修复写成该截图全部折线都已消失。同一政治事实的着色和线是否还有源级精度差异，仍需对应画面与确切位置。

## 6. 时间与重复工作

保留`FormalWorldApplication._on_world_changed()`已有规则：普通日期只更新`political.display_date`；只有显示资料有效期真正改变才refresh地图。经济观察仍按原选择及领域修订刷新，不改结算。

加载请求继续不以普通小时/日期作为物理几何重制键。新增完整包含复用：当前已安装或在途的有界分片集合若已包含本次全部需要、且政治ink开关相同，缩小视野不再取消同一工作。没有累积全球精细片或无限日期缓存。

没有新增纹理、Shader采样、模型、材质种类、相机、视口、物理底图或缓存管理器。原按批次材质、上传与离场释放沿用。不能据源码推断FPS、风扇、内存或缩放耗时已经改善；首次历史CPU几何、驱动提交及正式领域合法工作仍有成本，主要耗时没有本轮测量依据。
