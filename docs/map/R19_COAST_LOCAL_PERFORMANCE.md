# R19：海岸、LOCAL与推进显示三轮修复

施工基线为本机R18。已先读R17、R18说明，再按海岸几何、LOCAL合成、推进与资源三轮实施。每轮修改后重读调用方、资源安装和退出路径；最后集中阅读本轮修改。只生成一份最终预览。

未启动游戏，未运行测试、性能采样、截图、哈希或额外门禁。未操作Git。本文是源码施工报告，不是运行验收。没有改经济工作线领域实现。

## 第一部分：海岸和地图几何

### 来源和已有规则

物理陆地与海岸仍来自已有Natural Earth固定版本及其全局统一简化成果，比例尺1:10,000,000，现代物理参考。政治底网仍是现有1900历史几何。行政显示仍来自各国既有历史GIS。河流仍使用原Natural Earth或Sandre/IGN等有来源的中心线。

物理补充陆地和海洋修补面只是显示差量，不赋予政治身份。历史政治、行政、水文和现代物理边界不被强制改成同一事实。R18删除圆形海岸替换、逐三角扩张和重复描边的处理保留，不作为R19新增成果。

### 第一轮实际修复

**1. 共享物理网格缺少第二个地平线扇面。**

`LocalSpatialLod.prepare → GlobeSurfaceBatch.encode`原来把战略面按regional_reference编码，只保留一个扇面。然而同一Mesh也进入WORLD。球面前后半球裁切能把三角形裁为四边形，需要两个扇面；仅有第一个会遗漏可见部分。此问题与海岸来源差异无关。

R19统一为两个精确边扇面，每个三个顶点。沿用Shader原有槽位0、3、4、6、9、10，保留地平线裁切的全部面积。R18已取消扩张，因此原政治面12顶点、24索引中的重复角点和退化三角已无用途；现在每个源面为6顶点、6索引。物理面也保留完整两个扇面。删除regional_reference、zero_expansion及其失效编码分支和计数字段。没有再造多边形、扩大陆地或更改原环、孔。

**2. 闭合海岸在打包首尾仍可能出现端帽。**

R18只在128段块之间传递邻点，没有为闭合源环的第一块和最后一块传递跨闭合点邻点。现已补齐before/after。`GlobeProjection.display_line`还将明确闭合的源环末点复用首点编码，避免经度展开360度后留下浮点尾差。只处理源数据本来闭合的环，不把开放河口或分片边界强行连起来。

**3. 行政裁水曾使用请求状态，而非已安装状态。**

R18从`StrategicSpatialLoader.content`取裁水几何和来源键。加载开始时content会暂时为空；新content返回时，相应GPU LOD可能尚未安装。这会造成行政线清空重做，或提前按新水域裁切，而画面仍使用旧物理LOD。

现在由已有`LocalSpatialLayer`在完整物理LOD安装时发布其物理来源键和当前海洋修补多边形。旧GPU批次承担交接时，同步保留这一份必要引用；新LOD就绪后一起替换；release/clear一并释放。来源键只包含实际物理对象ID和LOD，不因交通或城镇分片变化重裁行政线。没有第二套缓存服务，也没有复制原始GIS。

行政后台线程继续只裁显示墨线。原行政多边形、拾取组件、成员及面积关系不变。线程持有的旧输入只保留到其结束，不会被下一批安装原地清空。

**4. 画成海洋的位置仍可能命中旧政治陆地。**

原`_gui_input`先查行政和历史政治底网，没有检查当前可见ocean_reference。某处已被物理修补面画成水域，旧政治底网仍可能返回陆地对象，使空白海洋点击不能取消选择。

R19让当前海洋修补面保留必要的有界拾取面。只有确实命中当前可见修补三角形、且没有真实地点符号命中时，才按水域处理；不扩大水域拾取容差，不推测缺失河宽。空白左键点击沿原`GlobeController.select`清除选择并通知原资料卡。拖动、滚轮、右键及HUD输入条件保持。真实地点入口优先，未改人物所在地或主权事实。

### 第一轮再检查与限制

重读了编码槽位与两个Shader的fan/corner解释、WORLD和REGION共享Mesh、LocalSpatialLayer的完整LOD安装/退休、行政裁切输入、独立拾取组件和海洋取消选择。陆地修补、海洋修补与岸线仍在同一当前LOD交接。没有删除孔、岛屿或历史边界来填补缺口。

仍需保留的差异：1900历史边界与现代岸线、测绘概化、填海及河道工程差异。Natural Earth不能提供近景海湾和小岛的测量级细节；中心线也不能证明河口岸线。这里只修正确定的编码、打包和状态错误，不保证全部复杂海岸已获实机确认。

## 第二部分：LOCAL三维与地表

### 已有正确实现保留

R18的黑色透明清除、预乘Alpha TextureRect合成、一对一采样和整数裁剪保留。没有再加透明层、模糊或覆盖矩形。REGION仍是完整二维缓存，LOCAL仍只有一个按需裁剪的三维目标。

重读了`_chart_transform`、`_update_local_camera`、`_chart_pixel`、裁剪尺寸/偏移和`surface_unit_at`。正交相机偏移、裁剪原点及射线像素换算继续共享原地理投影，没有新增屏幕补偿或第二相机系统。没有发现需要再乘一次Alpha或调整经纬度的依据。

### 第二轮实际修复

**1. 已退休场景的缓存图像可能继续显示。**

当旧地表因投影框架变化退出，而后继仍在准备时，`update_landmarks`可能在“没有地标实例且没有已安装地表”分支直接返回。此时旧LOCAL纹理仍可见，即使它所描绘的节点已经退出。

现在只在这种没有有效三维显示内容的等待状态撤下旧纹理，停用该目标更新、清除呈现标记，并让二维缓存更新一次。相同投影下仍有效的旧地表继续承担原交接。后继安装后沿现有流程重新呈现。不是关闭LOCAL或把有效地形隐藏掉。

**2. 隐藏模型的旧标记仍可能压住地图符号并接收点击。**

`landmark_visible`原来只查“曾呈现、实例存在、边界存在”，没有检查实例和裁剪目标是否实际可见。`_place_at`又直接使用残留边界。现在地图符号退出和模型命中都要求当前呈现与实际可见状态一致；建筑入口也要求LOCAL目标可见。等待地表的隐藏模型保留原地图符号。

**3. LOCAL明暗使用了REGION入口方向。**

精细地形顶点和法线存于固定REGION投影框架，但地表Shader把该框架的方向当成真实东西南北使用固定灯光。同一地点从不同入口进入REGION，坡向明暗可能不一致。

现使用已有`RegionProjection.tangent_axes / _geographic_basis`，在地表材质安装时给出该资料锚点的法线变换。Shader先把原真实网格法线转回当地东/上/南方向，再计算原双方向明暗和坡度色。没有更改顶点、海拔、光照幅度或增加另一层坡度增强。局部变换以有限资料锚点为基准，不声称是跨垂直基准的测量级地表拼接。

**4. 停用颗粒材质后仍生成整套无用顶点UV。**

R18移除了LOCAL颗粒采样，但`TerrainPreparation._make_surface_mesh`仍逐顶点执行另一套局部投影、96米相位、UV数组复制、裁水插值和GPU UV上传。R19删除这些无消费者的数据准备。实际高程UV2、边缘覆盖Alpha、法线、孔和精确拾取三角保留。坡度从变换后的同一法线计算。

### 第二轮再检查与限制

重读了地表准备完成、安装、旧节点释放、地标加载、MultiMesh公共变换、裁剪目标、呈现回调和拾取。现有模型仍只在适用LOCAL近景启用，REGION符号仍走原规则。没有重新建模或增加建筑。

WORLD约39.1千米、REGION约9.8千米的现有ETOPO衍生，四处原生60秒中尺度差量，以及巴黎IGN、伦敦EA DTM、采尔马特swissALTI3D和吉萨Copernicus DSM均保留。原精细尺度阈值、35%退出迟滞、真实边缘高度和R18中尺度近景退出带未改。未重建原始数据。

仍缺：更大范围原生精细地形、垂直基准转换、完整河岸和水位、适用年代的土地覆盖。吉萨DSM仍不是1900裸地DEM。有限资料外继续显示可信较粗地势，未填入随机山峰或纹理。

黑框是否完全消失、边缘是否自然、建筑尺度和明暗是否达到视觉目标，均仍需玩家运行。源码复查不能替代画面确认。

## 第三部分：4×时间推进和性能

### 正式时间链路

`0.25秒Timer → TimeControl.tick → advance_requested(15×speed分钟) → FormalWorldApplication._advance_world → SimulationStep.advance_minutes → GameClock及正式领域 → _on_world_changed → 实际需要的展示更新`。

4×每次推进60游戏分钟；1×每次15分钟。暂停不发推进请求。SimulationStep继续按日界、旅行、运输、消费和生活安排等真实边界依序执行。

保留工资、经营时间和日结、运输窗口、到达通知、消费、宏观区间、生活安排、迁居、范围调整和组织日审。`GameClock`、`SimulationStep`及经济领域文件未改，没有减少结算次数或改变区间规则。

### 第三轮实际修复

**1. 相同后台几何需求被相机变化反复取消。**

行政准备原来在每次平移时重新枚举需求；国家边界行又包含随屏幕中心改变的anchor/angle。即使地理准备窗口和LOD不变，Dictionary需求也不同，导致增加generation、丢弃分批上传并取消相同几何准备。

现在：

- 在同一有界准备窗口、同一尺度及修订内，平移只更新可见状态和相机uniform，复用需求。
- 国家边界后台裁切帽由同一扩展地理准备窗口确定，不随每次屏幕中心变化。
- 缩放仍按实际尺度查询合法行政层级。若实际对象、LOD和准备窗口没有改变，不重启原任务；改变后仍取消过期请求，最终有效结果必须安装。
- 日期使用完整观察日期参与现有显示需求判定，避免只按年份遗漏合法日期变化；需求相同仍复用，不把普通跨日变成几何重建。

没有扩大缓存范围、删除行政内容或改写滚轮和35%迟滞。

**2. 地图资料完成误刷当前人物或经营页面。**

R18合并了同帧refresh，但`_on_place_content_ready`只要存在地图选中地点，就会刷新当前页面。LOCAL加载分多帧完成时，即使用户正在看人物/经营页面，也会重复进入其Presenter查询。

现在该入口只刷新实际可见的地图资料/百科/行政页面。人物和经营页面仍接收本身真实状态变化。隐藏WorldPage也不再更新空间上下文或显示专用资料副本。返回地图时仍按原页面入口读取当前资料。

**3. 后台结果缺少世界实例所属检查。**

读档会替换`spatial_world`。原行政准备只比较generation；如果新世界尚未来得及执行下一次地图需求同步，旧结果可能向新世界安装拾取组件或覆盖摘要。

现有线程和分批上传增加其实际世界实例引用。只有来源仍是当前世界且代数有效的结果才能安装；否则丢弃并请求当前地图需求。完成上传后释放相应所属引用。不改存档结构、世界事实或加载算法。

### 已有合理实现，不重复施工

- R18普通跨日只更新观察日期；经济展示快照按页面和revision使用；国旗按引用更新。保留。
- MainShell时钟只重画时钟数值与当前时间标记。普通时钟未被发现会进入地形或GLB重建。
- 当前LOCAL视图键相同会返回；相机参数、裁剪尺寸和材质值有既有复用。TextureRect不会替项目持续申请UPDATE_ALWAYS。
- frame_post_draw只发布必要的呈现完成变化；`_on_local_frame_ready`不请求另一轮三维场景准备。未发现需要删除该通知的证据。
- ResourceLoader仅在加载状态完成后取PackedScene；最多两件近期场景缓存、现有实例和共享MultiMesh继续使用。没有改回逐栋Node3D。
- 新旧地形交接、过期任务取消、8×8拾取候选块和离场释放继续沿原路径。没有新资源管理服务。

### 一件GLB仍可能附带哪些成本

首次进入LOCAL仍可能涉及场景加载/实例化、Shader首次准备、原生DEM后台准备与主线程Mesh/纹理安装、三维环境/相机/灯光、地表/覆盖/模型、裁剪渲染目标及一次二维合成。相机缩放时，仍需更新真实显示图像。模型文件大小不能代表整条路径成本。

地表实际覆盖窗口时，裁剪三维目标可能接近全窗口；单个模型本身的包围盒不应直接等于全窗口。原一对一像素密度和已有裁剪规则保留，没有降低全图分辨率或限制到30FPS。

R19明确减少的是上述已定位的需求重启、无用UV、失效扇面编码及不相关页面转换。不能据此断言某类成本是风扇、卡顿或约1GB驻留的唯一原因。驱动、GPU透明合成、主线程上传、行政准备、可见经营查询、正式日结和整机换页仍无法排序。

### 资源变化与未来120件古迹

新保留的CPU引用仅用于当前物理LOD的水域精确命中和行政显示裁水。替换时退休，后台读者结束后释放旧输入；没有保留全球多级几何。水域拾取需要面与包围盒，因此不能声称本轮所有内存类别都会减少。GPU面槽位简化也不等于实测显存下降。

当前仍是有限LOCAL资料源、最多两个主要战略区域和最多64个海岸分片、两件近期PackedScene缓存及当前可见实例。两件场景缓存不是“两件模型的世界总容量”，也不是活跃实例数量上限。相同近景中若以后纳入大量独特GLB，仍可能增加材质、Mesh、实例化和绘制成本；尚无120件密集同屏容量结论。原云端120件没有导入，许可和1900形制问题仍在。

## 第四部分：最终交付

### 三轮完成内容与共同原因

第一轮修正共享网格的地平线扇面、闭合岸线邻点、已安装物理LOD与行政裁水的一致性，以及可见水域仍命中旧底网的问题。

第二轮修正无有效场景时的旧缓存图像、隐藏模型的符号/命中状态、法线照明方向，并清除无用颗粒UV准备。

第三轮修正相同需求反复取消、地图完成信号误刷其他页面、旧世界后台结果可能安装到新世界的问题。集中整理还核对了闭合点编码、完整日期依赖和临时所属引用释放。

共同原因不是模型文件太大，而是将请求状态、已安装资源、已呈现图像、可见页面和正式世界实例混用。每条修复都在原所有者中处理，没有新的地图运行时、Presenter或世界状态。
