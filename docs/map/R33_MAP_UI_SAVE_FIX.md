# WWO R33 — Map, UI and Save Compatibility

日期：2026-10-17。基线：本机最新 R32。引擎：Godot 4.6.3 Compatibility。

R32 未通过整体画面验收。本轮完成地图数据消费、查询资源、UI 和存档识别修改。原 R33 及补充存档要求分别进行了限定的隔离存档会话。没有开展一般地图试跑、旋转/缩放巡检、性能采样、回归、哈希核验、CI 或 Git 操作。

## 1. 政治矩形：确定的问题与未确定的部分

确认一条实际职责混用。`GlobeRenderer._on_current_land_changed()` 原先将 `historical_initialization_eligible=false` 直接视作需要用正式土地单元重切历史国旗的条件。但 `SpatialWorld` 在实际控制变化、显式行政归属修改及非历史初始化拆分时，都可能清除此标志。这不是“主权已改变”的专用标志。

旧路径会把土地单元的生成分区边缘带进政治填色；同一初始国家内也可能出现分区切边。该路径还会裁掉单元内的旧历史国界，或生成不该由行政/控制变化触发的新主权显示线。

本轮仅改渲染消费：读取当前主权，与种子中对应单元或祖先的初始主权比较，给显示输入明确的 `sovereignty_changed`。主权未变时，继续保留历史 ink 的填色和国旗。控制仍由原正式控制状态提供；控制变化不改变法理主权。行政关系仍由原行政系统保存。

政治三角形切分、历史国界显示裁切、新主权线均改为遵守这一条件。实际主权变化仍可按合法土地几何更新，没有冻结正式状态，也没有修改领域算法。

**这一错误不能解释所有截图。** 国家选择页尚未绑定正式土地状态时，也可能出现用户描述的异常；俄国大范围与 REGION 的全部矩形边缘，仍未找到能锁定每张截图的唯一直接原因。不能把本次语义修正说成所有矩形已消失。

本轮进一步读取欧洲、欧洲中片及亚洲两个粗片的逐国家 ink 分组，而非只比较总面积。法国、英国、德国、俄国的分组与对应原历史范围比较，超出面积仅为坐标精度余量，未发现将整个分片直接分给这些国家的源文件错误。没有因此重制 geom/ink 或修改 CShapes。

## 2. 本轮的国旗与 UV 修改

- 国旗改用明确的 `flag_texture` 材质采样器。物理面数据仍用 `face_data`。切换国旗不再清空 CanvasItem 并重新提交 Mesh 命令，也不再借用画布内置 `TEXTURE` 的绑定。每个批次仍只取自己的已解析国家样式。
- 三角形的三个 UV 顶点使用同一个经度换周偏移。原来逐角点独立取整，在纹理经度换周位置可能让同一三角形的 UV 相差一周。该修改不移动地理顶点，也不改变国旗图片。
- R32 的 `VERTEX_ID`、六顶点/双裁切扇面与面数据纹理格式保留。本轮没有再把同一套顶点有效性检查重复申报为修复。
- WORLD 与 REGION 使用同一源球面顶点和国旗参数，只在既有投影公式中区分观察方式。没有为国家增加坐标偏移、遮罩、关闭国旗或恢复 CShapes 拼陆地。

上述修改去掉了不必要的绘制命令重建，并处理了一个 UV 连续性风险。**没有证据证明内置 TEXTURE 或显卡驱动就是全部矩形的根因。** 没有进行本轮 REGION 画面验收。

## 3. 首屏与菜单内存：实际移除的工作

R32 虽然已让物理底图先显示，但首屏仍对所有历史国家执行 `source_mesh()`：分环、孔洞处理、分区三角化、球面细分，再由 `PoliticalLayer.bind_source_meshes()` 制作政治查询面，最后由 `GlobeSurfaceBatch.prepare_picking()` 保存逐面查询字典。这些数据不再负责正式物理陆地绘制。

现在 `prepare_source_geometry()` 使用 `GlobeProjection.source_reference()`。只准备原历史环、内孔、范围、旗帜构图范围和原边界线。国家查询通过这些历史多边形解析身份，保留经度换周、孔洞及有史料依据的局部显示掩膜。普通国家仍有原四像素近岸/小岛边缘辅助。受局部政治掩膜约束的身份按掩膜内部查询，不能借整个旧国家面认领未知地理。

菜单不再创建全世界历史查询三角形，不再持有对应的政治面副本及逐三角形查询字典。国家样式字典与 REGION 样式只保存样式，不再引用历史面查询对象。

正式物理显示批次原本也为拾取保留每个球面三角形的点、UV 和 AABB。现在物理拾取读取同一已安装版本的原物理多边形及内孔。加载器准备紧凑的多边形查询环；面编码不再附带永久逐面拾取字典。物理范围不会因为没有政治颜色而变成海洋，也不会从物理拾取结果推断最近国家。

旗帜构图仍拟合主连通分量。主分量现在按源环面积及纬度权重选择，不再为此先生成整套球面三角形。图片、比例参数和历史身份没有修改，最终构图仍需用户查看。

已有全球共享国界衍生线可用时，不再先重建全世界原环的共享边，再把其中多数结果丢弃。只在原有局部史料掩膜作用范围内保留必要的源边处理，其他地区复用已有共享国界文件。没有删行政数据或降低海岸质量。

**没有测量首次加载用时或内存，不能承诺从约 10 秒缩短到某个数字，也不能宣称降低了多少 MB。** 点查询、物理 LOD、纹理、历史资料及合法世界初始化仍然有成本。

## 4. 生命周期及仍会保留的资源

仍会持有当前有效物理源多边形、当前 ink 源数据、当前 LOD Mesh、RGBAF 面数据纹理、国旗纹理、原始历史查询环及当前地形资源。它们各有现行消费者，不按 EXE 大小推断其内存。

政治升级中仍会短暂同时存在旧有效批次和新暂存批次；完整安装后替换并释放旧 RID。R32 的同范围海岸复用、物理先行、失败保留、过期丢弃及有界 LOD 规则保留。没有新增第二套底图、全局缓存或完整地球。

检查了菜单到正式世界的现有转交：菜单将 Renderer、Controller 和内容转交给正式场景；正式场景释放其默认 Renderer/Controller 后接收，不另外保留完整菜单地图。回菜单时原世界场景离场，Renderer 释放现有 RID、线程和区域资源。这些路径原先已有，本轮没有重复宣称为新修复。

未发现足以从源码宣称“所有菜单内存负担已解决”的依据。极端视野下的临时峰值、实际驱动资源及反复进出场景后的实机内存仍未测量。

## 5. 国家选择页及 UI

- 从国家/身份选择页移除“返回主菜单”按钮。它原来只绑定共享的 `_show_page("home")`，没有独立处理函数需要删除。减小该页现有容器间距，保留国家、身份和进入世界。
- 加载失败时的返回/取消、重试，以及窗口退出路径均保留，没有删除故障恢复入口。
- 正式世界系统/设置弹窗改为按窗口可见范围右对齐，保留边距并放在时钟下方。音量两按钮宽度改为从面板可用宽度计算。原面板随时钟缩窄、按钮仍固定占用 244 像素，是能确认的越界条件。
- 时钟按钮本来留有右侧边距；未确认需要改变其机械美术或几何，本轮未改。
- 普通地图反馈去重，在原消息历史中保留记录；普通地图提示显示约 2.5 秒后淡出。有操作链接时才占用通知区域的点击。无操作的成功/准备提示不阻挡地图点击。错误仍可在现有消息抽屉查询。
- 菜单地图成功状态约 3 秒后收起，准备中及明确失败文字不按成功提示处理。没有增加加载超时判定或新消息系统。
- 主菜单加载页的槽位说明增加最小高度，保留两行摘要、溢出省略和完整提示，避免版本说明被布局压没。此项在原 R33 隔离会话后按实际看到的问题修正；补充要求后的资料入口另行核查。

未全面翻新 HUD。底部黄铜半球仪、时钟美术、星轨、国旗、人物饰盒、日志和油画不改。设置内部展开的最终效果尚未单独实机核查。

## 6. 存档格式与识别

外层仍为 `formal_world_exact_variant_v1`，内层快照仍为 `formal_world_simulation_v15`。JSON 外层中的 Base64 保存 Godot Variant 二进制载荷。游戏施工编号与存档格式版本是两件事。

原五槽不变：自动槽 0、手动槽 1—4。旧单文件 `formal_world_1900.json` 仍通过手动槽 1 的既有兼容入口读取。原临时文件、验证、备份和原子写入保留。读取失败不会保存新世界覆盖原文件。

### R33 补充：创建来源与最后写入来源分开

新存档外层新增可选 `save_metadata`，其元数据格式为 `formal_save_metadata_v1`。快照仍为 v15，不改变经济、人物、土地或其他正式世界字段。创建游戏版本、创建时间、最后保存游戏版本、最后保存时间分别记录。版本从 `project.godot` 的 `application/config/build_id`、`build_label`、`version`、`build_sequence` 读取。R33 构建 ID 为 `wwo-r33-internal`，顺序为 33，不从 EXE 文件名推断。

第一次保存新世界时记录创建信息。后续保存、读取后继续保存及另存保留创建信息，只更新最后保存信息。只有原子写入成功才更新运行中的来源资料。读档本身不改写文件。旧档未记录创建版本和创建时间时，保留 null；即使以后由 R33 明确另存，也不把它伪装成 R33 创建的新世界。原始格式及迁移历史随来源资料保留。

旧 `ui_summary.build_label` 只能说明最后写入来源，不能证明最初创建版本。文件时间不作为创建版本或创建时间的证据。无此资料的旧档显示“旧版存档：创建版本未知”。

五槽列表区分当前版本、旧版本且格式兼容、创建版本未知、需要转换、版本不兼容、存档损坏及读取失败。主菜单及游戏内槽位均增加“资料”按钮，列出创建/最后保存版本、外层/世界格式、两项时间、原始格式、迁移记录和可读原因。不会把无法读取的文件显示为空槽。

列表执行现有文档解码，检查声明格式、载荷及元数据，不为五槽分别构造完整世界。能够解码后，实际读档仍执行既有世界引用及状态校验；列表的“可以读取”不取消这些约束。

本版支持 `formal_world_exact_variant_v1` / `formal_world_simulation_v15`。已知较早 v1—v14 顶层快照被明确标为“旧版存档，需要转换”，同时提示本版无转换器，不能直接读取。其他未支持格式显示“版本不兼容”。没有自动迁移按钮、自动改档或补造世界字段。保留原子写入、临时文件验证和备份规则。没有声称所有旧格式都能转换。
