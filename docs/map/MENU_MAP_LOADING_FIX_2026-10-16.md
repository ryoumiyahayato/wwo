# 主菜单地图加载修复

日期：2026-10-16。基线：当前R29正式源码。Godot 4.6.3 Compatibility。

本轮实际修改加载代码，没有修改地形、林地遮罩、模型、海洋、历史数据、主权/控制、经济和军事算法、存档、GameClock或黄铜半球仪。没有启动游戏、运行自动测试、回归、采样、探针或哈希核验，没有Git操作。

## 1. “正在准备地图”的控制位置

`scripts/formal/formal_world_menu.gd`：

- `_prepare_preview()`开启加载画面，启动原地图工作线程。
- `_read_preview()`读取来源、历史显示资料、国家身份，调用原 `GlobeRenderer.prepare_source_geometry()`准备历史拾取/边界及旗帜参考。
- `_process()`只在线程结束后取结果，校验后排队安装。
- `_install_preview()`在主线程安装原地图节点、绑定来源几何并refresh。
- `_set_loading(false)`关闭遮罩；成功、明确失败和用户返回主菜单均有出口。

点击“进入世界”使用另一个工作线程，不与菜单预览混为同一状态。正式世界仍按原规则建立及加载。

## 2. 已确认并修复的错误

### 必需资料读取失败被忽略

原 `HistoricalLoader.load_current()`的失败返回值未由 `WorldBootstrap.prepare_presentation_content()`处理；菜单又可能将带errors的对象包装为 `error=""`。

现在HistoricalLoader明确记录 `loaded`。地理、行政、国家显示及地图显示描述文件失败即停止后续准备，保留具体错误；子加载器返回false却未给错误时补充明确说明。Bootstrap检查来源是否就绪并处理load_current返回值，返回明确的失败对象；菜单检查loaded/errors，不对失败内容生成几何或安装地图。

现有历史必需资料仍按原准入规则处理，没有为让地图打开而跳过国家或行政数据。LOCAL模型、可选物理分片/政治墨层、relief纹理仍走原按需加载，不被加入菜单必需资料列表。没有以缺少可选近景内容阻止菜单打开。

### 后台结果未校验

原来直接把线程结果转成Dictionary并读取字段。

现在先检查线程启动错误码、is_started和is_alive。只有已结束线程才wait_to_finish；结果保持Variant，先验证实际类型，再检查error、HistoricalLoader、loaded/errors、MapGeometryContent、历史政治视图、几何字典、每个既有feature的几何字段及非空拾取三角形。带日期的结果还验证日期类型和字段。没有用缺字段、空几何或失败线程冒充成功。

### 失败后重复进入准备、安装错误留下遮罩

原失败处理调用_show_page后可能再次自动触发准备；运行时异常也可能在解除遮罩前中断。

现在统一 `_fail_preview()`：关闭遮罩、移除失败的临时地图节点、清空待安装内容和国家列表，保留具体错误和原主菜单交互。存在错误时不再自动调度准备，用户点击“重新准备地图”才重试。

安装过程没有await。进入安装前保留一个进行中标记；正常结束立即清除。若脚本错误中断该同步流程，下一次正常UI处理发现残留标记，会按安装中断收尾，不继续永久保留遮罩。若调用返回失败但未提供错误，同样给出明确失败提示。

菜单只在国家记录、可选国家列表及原Renderer源几何绑定完成标记有效时设preview_ready。检查的是初始化完成，不是假称GPU画面已验收。

### 不必要的绘制等待

原 `_install_preview()`在安装中await process_frame，安装后await RenderingServer.frame_post_draw，最后才关闭加载画面。后一个条件将菜单可操作性绑定到绘制事件，窗口未绘制时不能保证该事件及时出现。

现在结果到达后先更新“正在安装地图”，下一次正常UI处理执行安装。完成初始化后请求正常重绘并解除遮罩，不等待RenderingServer信号。没有跳过configure、源几何、refresh或国家解析，也不等待全部物理LOD/三维模型。

正式场景接收菜单遮罩时也按安装成功/明确失败释放，取消对frame_post_draw的依赖；其原场景初始化process_frame保持。正式场景增加加载失败保护，避免Bootstrap现在明确返回失败后仍安装不完整内容。合法世界建立、结算及保存语义不改。

## 3. 失败和重试的实际行为

线程无法启动、返回类型错误、必需资料失败、几何缺失或安装中断，都显示“地图准备失败：具体原因”，关闭加载遮罩。原国家选择页提供“重新准备地图”和返回主菜单；进入世界按钮保持不可用。没有无限自动重试。

加载画面增加一个同风格的“返回主菜单”按钮，仅在菜单预览准备时出现，不用于强制中断正式世界建立。返回时使本次generation失效，隐藏遮罩并回到原菜单。工作线程按已有阶段边界协作退出，过期结果丢弃。

不会强杀或join仍在执行的地图线程。旧线程结束前不会启动第二个地图请求；用户提前重试会看到“上一地图请求仍在结束”。整个过程只有原来的一条菜单工作线程，没有另建加载器或地图运行时。

## 4. 实际阶段信息

现有加载标签按实际代码阶段显示：读取地图资料、读取历史地图资料、读取历史行政资料、读取国家显示资料、准备历史国家、准备历史拾取与边界几何、安装地图。

同一后台阶段超过15秒，标签补充“仍在处理，可返回主菜单等待”。这只说明阶段尚未完成，不是失败判据，不会把超时当成功。沿用原不定进度条，不伪造百分比。

后台线程只通过Mutex更新简短阶段文本和读取请求代号；场景树、材质、按钮和标签操作都在主线程。

## 5. 首次准备工作量

确认原日期索引 `_collect_display_dates()`会递归走GeoJSON coordinates数组，而这些数组只包含数值坐标，不含valid_from/valid_to。现跳过该字段，仍扫描其余有效时期元数据。没有修改坐标、几何精度或日期规则。

没有确认可安全移除原全球历史拾取三角化：当前国家拾取、边界和旗帜参考仍使用它。本轮保留 `GlobeRenderer.prepare_source_geometry()`和 `GlobeProjection.source_mesh()`，没有删国家、降低物理海岸精度、恢复政治面拼陆或新增第二地球。

取消请求只能在原读取阶段及历史几何准备前后检查；单次source_mesh内部仍是原有限几何工作。返回主菜单不强杀它。其实际耗时及用户原卡住位置没有通过本轮运行确认。

## 6. 并发修改

调查期间GlobeRenderer仍出现外部写入时间变化。本轮没有修改该文件，也未覆盖、还原它或其他工作线。只对下面加载文件的相关段落应用补丁。正式世界应用文件只调整地图资料失败出口及加载遮罩交接，不改领域算法。

本轮不追赶其他工作线反复导出，不宣称全项目已冻结。R29地表Shader、RegionView、LocalSpatialLod、正式GIS和模型资源均不改。
