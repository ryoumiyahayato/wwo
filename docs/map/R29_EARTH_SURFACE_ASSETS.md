三件生成器均为 `ProceduralLandformGLBBuilder/5.0-GodotOptimized`。内嵌声明均为 `CC0 / Game & Godot Engine Ready (8x8m Modular Grid)`。这是资产自身的声明，没有独立作者、生成工具条款及来源链证明，不能据此宣称全库已获商业发行许可。三件均未进入运行目录或正式 Release。

实际形制与用途：

- 三件都有8×8米地面、向下伸出的地质底座、合并障碍物 Mesh。林地障碍物不是逐株独立节点，内含模型局部地面高度。直接去底座后整体摆放，仍不能让每个元素正确贴合采尔马特真实坡面。
- 山地最高约2.57米，是模块局部造型，不是阿尔卑斯的测绘高度。放大覆盖 DEM 会改变真实山谷和坡形，不采用。
- 平原地表在约−0.085至0.329米间起伏，带独立障碍物和底座；没有巴黎或伦敦的建成区、道路或绿地依据，不重复排列为城市地面。
- 林地顶点色地表中位 RGB 约(0.220,0.439,0.204)，障碍物约(0.255,0.424,0.204)。只参考其绿色方向和共享材质方式；WWO 使用更低饱和的(0.34,0.41,0.33)，没有逐顶点复制艺术覆盖。
- 两个材质均非金属，粗糙度分别0.85、0.95，使用顶点色。当前 WWO 地表已有便宜的制图式 Shader，不另建 PBR 材质、纹理或灯光来照搬这些参数。

底座、局部比例、合并障碍物和缺少配准使三件均不满足直接进入当前真实地图的条件。它们仍有风格参考价值。秋季/冬季版本、沙丘、河滩、冰川和岩石等其余条目只读到目录，不宣称已逐件检查造型。没有凭名字认定其适合1900年或某个地点。

三个原样本保存在 `local-artifacts/r29-surface-reference/forest.glb`、`mountain.glb`、`plain.glb`，仅为本地参考；导出预设排除整个 local-artifacts。没有创建抽取树木、碰撞、寻路或地貌实体。

## 3. 云盘导入脚本的具体问题

- V6和V8原文都调用 `ArrayMesh.generate_tangents()`。现有质量报告已指出 Godot 4.6.3 无该方法。本轮读取确认调用仍在，没有运行新的 API 探针，也没有将脚本启用。
- V6/V8将水体设为 Alpha、DEPTH_DRAW_ALWAYS 和双面。不能无条件照搬到 WWO 的物理水域和原合成路径。
- 样本的 Terrain/Obstacles 节点含 `-col` 后缀。直接采用原导入约定可能生成复杂静态碰撞；当前地图展示不需要这些碰撞。
- V8设置120米障碍物视距和淡出、180米底座视距。这是8米沙盘的局部单位，不能代替 WWO 的米/像素及地理范围准入。Compatibility 下的该效果本轮没有实际验证。
- 四份“.gd”元数据实际是 Google Docs。季节包把 Shader 放在注释中，另含 GDScript 控制器，不是一个可直接安装的完整脚本。
- 季节Shader的 `v_world_y` 实际赋值为模型局部 `VERTEX.y`，不能作为真实海拔或1900年雪线；按绿色程度改秋色也不是历史植被记录。六边形坐标控制器不参与正式地理或军事地图。

本轮没有修复这套未采用的导入工具。沿用现有 GLB 导入、共享 Mesh、有限缓存及释放路径。

## 4. 采尔马特：林地成为地表输入

保留 swissALTI3D 的33×63原高程格、原顶点、原三角形、法线和地理范围。保留2026-10-14取得的 OSM 林地来源及 ODbL 说明。它只是现代参考，不是1900年林地、经营权、木材产量或真实树木密度。

原路径在地表上方5厘米额外绘制1,793个林地三角面。地表和林地虽然共享材质，仍有两份坡面几何和 Alpha 边缘；覆盖色在多边形边缘切换。

R29实际改为：

1. 原 TerrainPreparation 工作线程把已有林地三角形按原 DEM 经纬度格映射为256×256、R8显示遮罩。只处理 `kind=woodland`，不从 DEM、海拔或政治色生成类别。
2. 原地表增加对应归一化 UV，在同一材质内将林地色按44%最大权重混合。林地、裸地共用同一个 DEM 高度和光照，不再有5厘米悬置的林地坡面。
3. 线性采样只在遮罩像素边缘形成过渡，没有增加大面积模糊边框、噪声或新的森林分布。遮罩像素约2.4×6.7米；细窄边界有栅格显示误差，原矢量事实不变。它不是新测绘数据，也不能用作土地面积、拾取身份或模拟判定。
4. 林地不再进入 `_make_surface_cover`。此路径只保留有效水面；删除覆盖专用的地表法线内插方法和无消费者的 `_surface_normals` 引用。

没有新增树木、岩石、草丛或 GLB 实例。没有改高程、雪线、冰川、行政身份、主权或控制。没有把无数据地区标成“没有森林”。

## 5. 四处 LOCAL 的已有地表改善

`local_terrain.gdshader` 由顶点阶段计算并截断明暗，改为插值真实地理法线后，在片元阶段归一化、计算原双方向制图照明。避免已截断的顶点亮度在整个三角形内插。不是增加高程细节或修改高度。

明暗范围由0.84—1.12调为0.78—1.20。沿用原光向、双光权重、真实法线、坡面中性色和绝对高度色阶。不增加随机纹理，不依据坡度判定裸岩或植被。政治/经济墨层仍是最后合成输入，R28在跨当前主权范围时退回中性 LOCAL 地表的规则保留。

| 地区 | 本轮实际改变 | 明确保留或未做 |
|---|---|---|
| 采尔马特 | 林地遮罩直接合成到真实坡面；应用新的法线明暗计算 | 原山脊/谷地、现代覆盖范围不变；没有历史森林、树密度或新增冰雪 |
| 巴黎 | 已有 IGN 地表使用新的法线明暗计算；保持中性地面及原墨层 | 建筑坐标、尺寸、贴地插值和塞纳河中心线不改；没有历史城市铺装、道路、绿地资料，不补造 |
| 伦敦 | 已有 EA DTM 地表使用同一计算，保留原建筑和中心线关系 | 不恢复已退役的宽河面，不造码头、堤岸或河宽；没有新的河岸覆盖数据 |
| 吉萨 | 原 COP-DEM DSM 地表使用同一法线明暗计算 | 不把 DSM 归为沙漠，不添加沙丘/裸岩模型；金字塔坐标、比例和地面高度不改 |

巴黎、伦敦和吉萨没有独立的新地态分类或城市材质。不能把共享光照调整写成已经补齐城市环境。建筑和独特地标的几何、贴地及数量没有修改；与地面的视觉关系只受地表明暗变化影响。

已退役的有限河面仍由 LocalSpatialLoader 排除，继续使用已有中心线。对于仍合法准入的水面，Shader直接保留原水文颜色，不再计算随后被覆盖掉的地表色阶和坡向；没有改变水面高度、岸线或遮挡规则。

WORLD和REGION保留 R28 的物理分片、政治墨层及 ETOPO relief。本轮没有修改其 Shader、增加地貌模型或第二份陆地。LOCAL和REGION继续共享原地理位置及高度色阶；本轮不宣称所有精度交接已经无缝。

## 6. 资源和显示成本

- 新 GLB、模型实例、地标、树木、灯光、视口、材质实例及完整地球：均为0。没有新增运行资产图片。
- 只有具有实际 woodland 输入的地表创建一张256×256 R8纹理，无 mipmap，像素载荷65,536字节；这不是实测显存。当前只有采尔马特。相应原生2079顶点增加 UV，共16,632字节名义数组数据。
- 同一地表的有效地面片元增加一次遮罩采样。无林地地区关闭该分支，不创建占位遮罩。没有多层纹理、实时摆动、透明植被、屏幕空间效果或每帧纹理生成。
- 删除原1,793个林地三角面及其单独 Mesh/节点的生成；没有通过减少 DEM 三角形获得这个结果。原数据中的林地三角形仍保留，作为遮罩制作的来源。
- 法线照明移到片元阶段会增加地表像素计算；工作线程新增有限遮罩栅格化。不能只列减少的几何而忽略这些成本，也不能由此断言整体更快。
- 原有水面走直接水文颜色分支，跳过不使用的地形调色运算。原政治 Shader、全球岸线批次和领域查询不变。

没有实测运行负担。LOCAL卡顿、滚轮延迟、4×风扇负担的主要归因仍未确定。本轮不宣称已经解决或降低任何百分比。

## 7. 加载、复用和退出

沿用 LocalSpatialLoader → LocalSpatialLod.TerrainPreparation → RegionView。遮罩跟随原地表和投影需求准备；没有新后台服务或缓存。工作线程只处理 CPU 数组；ImageTexture/材质安装留在主线程。

同一 source_path 与投影框架已安装时，原 `_update_surface_demand` 继续复用地表；缩放、相机姿态及普通时钟变化不重新创建纹理。过期工作结果的丢弃、后继安装和资源退休规则保留。

当前原准入计算的上限约为：巴黎21.26米/像素、伦敦15.65、采尔马特6.44、吉萨16.86。已安装内容保留到各上限的1.35倍；另需满足 LOCAL 激活和原地理视野条件。这是读取现有公式所得，不是帧率或负担测量，没有改准入尺度。

退出有效范围或投影更换时，原 `_release_surface_geometry` 同时清除林地纹理引用，原节点/材质退出；没有把它留给 WORLD/普通 REGION。材质只在原安装时绑定遮罩和开关，不逐帧重复提交。

三件既有内部预览古迹、普通建筑 MultiMesh、有限 PackedScene 缓存、离场释放、按需 SubViewport 更新保持。未修改 GameClock、SimulationStep 或任何人物、经济、组织和军事结算。
