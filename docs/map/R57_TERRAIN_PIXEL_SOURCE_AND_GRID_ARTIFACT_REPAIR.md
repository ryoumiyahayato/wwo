# WWO R57 — Terrain Raster Artifacts and LOD Integrity Recovery

2026-10-20更新：本报告对应初版R57，用户实机验收失败。后续源码整改、普通游戏窗口取证及同路径候选构建代数1见[R57实机整改](R57_GAMEPLAY_VISUAL_RECOVERY.md)。R57仍为CANDIDATE，R56保留ROLLBACK，未执行promote。

施工日期：2026-10-19。引擎：Godot 4.6.3 Compatibility。

本轮修正了已确认的分类放大、源支持域权重和精度选择问题。没有运行正式游戏场景。几何LOD提示未在有限资源检查中复现，不能写为已经根治。

用户补充的范围是法国、西班牙中距离，以及俄罗斯、奥匈、德奥、波罗的海和华沙邻区。没有取得对应截图的精确相机记录。下列坐标是这些区域的代表窗口，不是推定的截图坐标。

## A. 绿色方块与像素来源

### 取证路径

`trace_surface_r57.gd`直接读取保留的R56 EXE内PCK。使用包内的`MapRelief`、`GeographyLoader`、`RegionProjection`和`GlobeRenderer._surface_uniforms`。R57使用相同工具读取当前源码。两侧各120个指定点：10个窗口×800/250/75/35米每像素×左、中、右三个位置；窗口1280×720、方位角0。

工具读取实际`ShaderMaterial.get_shader_parameter`及所绑定纹理，不把目录候选当成已消费资源。记录路径、UV、编码、原生RGBA、覆盖权重、解码颜色、候选未采用原因。GPU隐式Mip写“无法直接取得”；CPU估计单列。上述运行没有启动主菜单、正式世界或模拟。

记录：`local-artifacts/terrain-r57/before_points.json`、`after_points.json`。前者的`build_label`为R56，选择解释接口标记为R56原实现，防止把重写的选择器当成基线。

### 已确认的分类放大

莫斯科代表点37.3°E、55.4°N、75米/像素：

|---|---|---|

| 文件 | `assets/maps/relief/european_r55_54_+36.bin` | `assets/maps/relief/repair_r57_european_r55_54_+36.bin` |
| DSM | 6角秒提取，约185米；显示格网217米 | 同来源；有限相邻缺口补取4个GLO单元 |
| 分类 | `european-surface-r55/cover/+54_+036.tif`，450×450/3度，741.3米 | 优先使用现有最细来源；该点仍约741米 |
| 制作 | 类别近邻放大，然后映射颜色并烘焙明暗 | 类别先映射颜色再面积重采样；DEM中性明暗独立保存 |
| 近景分类权重 | 1 | 0；保留DEM色阶、坡向与河谷 |

旧制作函数重建同一纹理，RGB最大误差0.001961、平均误差0.000981，符合8位量化误差。741米分类放大到217米输出，并未产生217米独立分类样本；75米/像素时，一个源像元南北约9.88个屏幕像素。规则块边与原分类格网一致。该误差来自制作采样，不需要假设GPU使用了过粗Mip。

另外取得37.26—37.34°E、55.36—55.44°N的小幅原生10米WorldCover研究提取。它显示原始林地、道路及耕作形态比450样本丰富。真实农业矩形仍可能存在，不能把全部矩形认作错误，也不能把741米格边当作真实田界。小幅原生提取没有冒充整个莫斯科的10米覆盖，也没有打包。

### 法国、西班牙不能套用莫斯科结论

法国2.5°E、47°N在R56的250米/像素下实际使用`canonical_r56_france_r42_46_+2`。它的原树木类别来自`france-surface-r42/trees/`中的2250样本/3度，约148米；不是741米。西班牙−3.7°E、40.4°N的250米/像素使用8度页，75米/像素使用`canonical_r56_shared_r48_40_-4`。

因此不能宣称用户在法国看到的所有格子都已证实来自450样本。中间页的869/1737米输出、与细片不同的烘焙方法，以及尚未捕获的实机绑定仍需区分。R57重制共同中间页，并重制这些窗口及相邻接缝真正消费的10张旧细片：法国3张、西班牙及比利牛斯3张、华沙2张、24°E西侧2张。它们采用同一源读取、色调和明暗方法。

制作器现在同时识别`cover/`与`trees/`的真实采样。后者仅证明2021年class10出现，其余类别未知；不会把未知类别补成耕地或草地。相同精度优先完整分类，较细的真实树木样本不被较粗分类替代。

另确认源目录层级遗漏：R45源实际在`spain-surface-r45/spain_r45/`，R46源在`benelux-surface-r46/benelux_r46/`；旧通用查找只检查父目录。R56虽可通过已烘焙细片保留一部分高精度，直接重建时却可能跳过这些原始DSM。R57明确纳入实际子目录，重制受影响页；西班牙代表点重新采用真实源制作的两度细片，不用ETOPO重建冒充旧GLO精度。

所有覆盖均为现代参考。原始类别和来源保留；近景降低不适用的分类对比度，不写入1900年土地、经济或军事状态。

## B. 地貌硬边

### 24°E支持域断层

24°E、51.2°N、75米/像素的R56实际绑定：

| 图层 | 有效来源/输出 | 点上覆盖与空间权重 |
|---|---|---|
| `canonical_r56_german_r44_50_+22` | GLO提取约185米，输出217米；分类约148米 | 旧源东缘A约0.499，贡献约0.499 |
| `fine_r56_50_+24` | GLO提取约185米，输出217米；分类约148米 | 已安装，A=0，贡献=0 |
| `euro_afro_russia_r56_base` | 120角秒概览，约3707米输出 | 承担细片未覆盖部分 |

`build_surface_r56.py::demos`在24—32°E示范域外框烘焙了1度支持域渐变。24°E恰是文件源域外缘；这一带实际已有GLO邻域资料，纹理却被制作成零贡献。此处不是“还在加载”。相同问题也作用于8—16°E、40—48°N示范域，德奥代表点12.6°E、47.6°N的旧细片贡献仅约0.353。

R57按真实已取得资料重制32张示范片，不继承这层人为零支持域。新编码明确区分中性DEM明暗与地理支持。24°E新细片`repair_r57_fine_r56_50_+24`贡献为1；德奥上述点也为1。最终离线对照还暴露旧德国片与新片分类权重不一致的接缝，因此同时重制`canonical_r56_german_r44_50_+22`及`52_+22`，两侧都采用编码6与同一权重规则，不把直线移到相邻文件外缘。真实DSM细节保留。

### 波罗的海：小矩形不代表更高精度

24.1°E、56.9°N：R56在250米/像素选择两度ETOPO片`european_r55_56_+24`，源间距1853米；点上因西侧边缘渐退只有约0.198贡献。旁边德国GLO片则为217米显示格网。两度片覆盖的矩形存在，并不意味着这一屏有同级细节。

R57在250及75米/像素选择`repair_r57_mid8_r56_56_+24`和相邻8度页；主片该点贡献为1。输出869米，DSM仍按实际GLO单元和ETOPO缺口逐项标记，不宣称均匀GLO精度。

### 通用选择修正

`MapRelief._choose_surface`仍以四个细片槽位和完整视野为约束，但比较真实源间距、输出间距和可见面积，不再总是先接受两度片。`source_step`使用已取得DSM单元范围计算贡献，缺口显式回退ETOPO；同来源信息量下用输出间距作小幅排序项。相邻边判断也比较源精度。

`explain_selection`按需调用同一选择函数，给出2/8/16度各组前四片覆盖率、源精度分数和资源ID；恢复原视野状态，不生成第二套选择器或缓存。已安装但贡献为零、排除的旧源、超过尺度和未进入完整覆盖组分别记录。

没有全局模糊、锐化或随机细节。中间页采用实际缓存高程及真实覆盖重制，而不是拉伸ETOPO后称为GLO。未取得的精细资料仍是缺口。非本轮有限区域的不同源精度，以及旧细片中的现代覆盖，不能全部写为已经消除。

## C. 几何LOD

原提示来自`LocalSpatialLayer._prepare_step`：工作线程结果的`lods`与当前`_wanted`不一致，或结果结构不完整。`LocalSpatialLod.prepare`原先把取消返回为`chunks=[]、lods=[]`，仅凭该提示不能认定物理分片文件缺失。

本轮没有获得用户失败当时的请求ID或线程栈，不能为其填写猜测的缺失分片。做了两个有限资源检查：

| 输入 | 实际结果 |
|---|---|
| 24.5°E、35.3°N，100公里范围、75米/像素 | `StrategicSpatialLoader.request`取得`physical_2_4_mid_1_0`；medium准备19批，上传后进入`cpu_ready`，`can_present_physical=true`，`update`发布同一medium ID |
| 巴黎原LOCAL资料 | 44个源分组；medium→local代数取消，再local→medium→local；local为47批，medium为20批，有限检查无完整LOD错误 |

路径是`request/poll → LocalSpatialLod.prepare → LocalSpatialLayer.prepare_step → update`。检查使用headless资源读取和dummy渲染服务器，不是正式游戏或实际GPU时序验收。原数据未在这两个窗口暴露缺失。

海岸案例走到`update`发布。巴黎案例核对准备、取消与安装，没有把它写成实际LOCAL画面验收。

R57取消结果显式带`cancelled=true`。线程包装记录请求代数、LOD、源组、物理ID、返回LOD和批次数。正常过期结果仍由原代数检查丢弃；当前请求意外取消单独报错；真正缺LOD仍报错并附具体描述，不隐藏提示，不把局部安装算作完整发布。诊断快照复制有限数组，防止后续缩放改变已记录的wanted值。

**未确认用户那次提示的根因，也未宣称已根治。** 保留已显示的完整物理版本和原回退；没有改相机、物理分片、主权或正式世界。

### 编码6

RGB保留现代覆盖与固定DEM明暗；A独立保存由真实高程色阶和坡度计算的中性明暗，不是WorldCover类别，也不是水域或历史土地Alpha。新资源具有完整矩形物理参考支持；其输出数据通道与旧编码分别解码。

有效分类间距取`max(原分类采样间距, 输出地理格网间距)`，覆盖色权重为` smoothstep(有效分类间距/8, 有效分类间距/2, 米每像素) `。不能把148米源烘焙进869米页以后，仍按148米边界使用。741米分类在75米/像素下不放大为地块边界；217米输出的较细分类在75米/像素保留约0.63，在35米/像素约保留0.026。DEM明暗不随覆盖色一起抹除。Mips对连续颜色和中性明暗分别面积平均，不平均类别编号。

编码0—5兼容路径、R56旧Mip修正仍保留。新增采样器0，新增6个标量权重；没有永久全屏诊断Shader。

### 默认关闭的实机入口

正常游戏没有新诊断界面、覆盖层或连续日志。需要复核时，用户可给同一EXE附参数`-- --r57-terrain-probe`，在地图上按住Ctrl+Alt并左击目标点。

每次只覆盖`user://r57_terrain_point.json`和`user://r57_terrain_pixel.png`。入口等待一个`frame_post_draw`，读取指定点的实际最终viewport颜色及33×33像素裁片，同时记录相机、逆投影位置、真正绑定的资源、源精度、RGBA、混合权重、候选原因和几何发布状态。最终颜色包含政治混色；CPU地貌重建单独标记，不能混写。GPU隐式Mip仍标无法直接取得。

诊断CPU读取通过`Image.get_mipmap_offset`截取原生Mip，已检查Mip1和最后一级读取；不是把CPU估算层级当成GPU测量。

本轮未自动启用该入口，也未取得用户失败画面的这类记录。法国中距离方格是否仍存在、未确定的几何提示、跨区连续缩放和约8秒启动体验，仍需用户实机确认。
