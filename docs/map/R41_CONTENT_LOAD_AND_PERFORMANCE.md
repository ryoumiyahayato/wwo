# R41扩展负载与性能实测

本报告接续[R41历史地物施工](R41_HISTORICAL_LANDMARKS_AND_SCENES.md)。实际增加2座桥、2座站房、7件内部古迹；另做4种只用于内部压力配置的原创设施。普通采尔马特林地从45个候选增加到67个。没有把测试复制件计为历史内容。

实际测量完成12次：A/B/C各3次后台运行，再各补1次前台运行。另有1次排除的诊断运行。完整政治地图仍需约7—9秒；WORLD旋转的R41帧时间比R40高，见下表。不能宣称启动和全球操作已改善。退出仍有1个CanvasItem RID及资源引用警告，R40同样存在，未定位。

## 3. 测量条件、隔离与原始数据

设备：i7-13700H（14核、20逻辑处理器）、16,886,784,000字节物理内存；实际使用RTX3050 Laptop GPU，NVIDIA572.83，Godot4.6.3 Compatibility。窗口与视口1250×720，VSync开启，60FPS上限不变。

A是保留的R40 EXE；B与C使用最终同一份R41 EXE。C在进入世界后明确启用高负载。未另外导出测试EXE。后台交错顺序为C1、A1、B2、C2、A2、B3、C3、A3、B4，每档3次；发现前台占比为0%，再补AF1/BF1/CF1，各一次前台运行。前台采样占比分别为99.3%、100%、100%。两组结果分列，不把后台样本冒充前台结果。

没有清理Windows文件缓存；不能把首次样本称为冷启动。启动时间含测试入口脚本的共同开销。原生EXE通过临时`override.cfg`进入排除打包的外部观察节点，再打开原油画菜单、原正式世界；相机操作调用原输入处理路径及已有定位方法，不另建地图。测试结束正常返回首页、退出进程，临时配置移出EXE目录。该观察节点不常驻正式游戏。

每次先确认`OS.get_user_data_dir()`为独立`WWO_R41_Perf_20261018_<标签>`目录，才打开正常菜单。没有调用保存、读档或转换；GameClock保持暂停。12次前后日期均为1900年1月1日00:00，菜单地图与世界地图的Renderer对象相同。B1诊断因地理覆盖层类型错误和采集端等待静止绘制信号而中止，只终止本轮隔离进程，未计入性能结果；采集端后来改读已稳定纹理，不再等待可能不触发的绘制信号。

12次有效游戏进程的累计存续时间约801.4秒。未跑长期经济模拟、全仓回归、CI或哈希核验。测试源码在`tools/map/r41_performance_driver.gd`、`run_r41_comparison.py`、`r41_gpu_sample.ps1`和`summarize_r41_comparison.py`；均被导出预设排除。原始事件、逐帧CSV、资源快照、进程/GPU记录、运行日志及截图在`local-artifacts/r41_performance/`，不进入发行包。

## 8. 实测后修正与未确认项

- 地理模式错误：`GlobeRenderer._sync_overlay_resources()`的条件表达式在地理模式返回无类型`[]`，赋给推断的`Array[Dictionary]`后逐帧报错。改成显式类型的空数组，再按政治模式条件赋值。B/C及前台补充均实际切换地理模式检查，未再出现脚本错误。
- LOD命名错误：Blender仅删除可见对象，隐藏旧Far占用名称，新包出现`Far.001`。生成器改为逐件删除全部对象，重制四件交通包。运行时原Near/Far规则继续使用，无需新增LOD状态或修改相机。
- 静止截图采集等待：外部工具等待`frame_post_draw`可能停在按需绘制的静止画面。改为读取已稳定的纹理；不是编写截图触发地图刷新的正式逻辑。
- 7件古迹索引按4件分页，避免沿用R23的三按钮单行溢出；资料中把示意尺寸标为“模型包络”。

没有修改R39相机、全球coarse/medium退休规则、海岸、主权、经济军事、GameClock或快照格式。R40行政实现保留；德国SVG配准、法国GIS/CShapes差异和比利时资料缺口没有因新增模型而解决。

有限截图已确认新模型出现。桥梁与现代水文的精确视觉接合、1900桥头细部、站房完整历史测绘、无DEM地标周边环境仍未完成。现有LOCAL最小2米/像素使部分建筑细部仍较小；没有为凑画面扩大古迹、复制城市或虚构地形。采尔马特基线截图也有有限高程窗口的深色轮廓，本轮未重新解释为真实岩壁。用户仍需查看美术、选择资料卡、跨尺度连续性和剩余行政错位。
