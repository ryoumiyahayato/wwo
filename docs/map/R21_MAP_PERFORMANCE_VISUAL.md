# R21：现有地图性能收敛与显示整理

施工基线：本机 R20 正式源码。引擎：Godot 4.6.3 Compatibility。日期：2026-10-15。

本文记录源码修改，不是运行验收。未启动游戏，未截图，未运行自动化测试、回归、性能探针、基准、CPU/GPU/内存采样、FPS 记录或哈希检查。未操作 Git。只执行最终 Windows 预览导出；结果见文末。

## 1. 当前渲染路径

| 层级 | 正式路径 | 渲染与资源 |
|---|---|---|
| WORLD | GlobeController → GlobeRenderer → GlobeProjection / PoliticalLayer / GlobeSurfaceBatch / GlobeBoundaryBatch | 原 HemisphereViewport 保存三维海洋半球、月球及二维政治面、物理差量面和边线。TextureRect 展示同一缓存纹理。固定太阳 Shader 通过地球观察矩阵受控更新。 |
| REGION | RegionCamera / RegionProjection → RegionView → 共享政治几何、战略物理 LOD、行政显示批次 | 原完整二维 SubViewport；有界后台行政准备与主线程分批安装；与 WORLD 共享不可变 Mesh，材质各自持有。没有另建视口。 |
| LOCAL | LocalSpatialLoader → LocalSpatialLayer / LocalSpatialLod.TerrainPreparation → RegionView | 已有地形后台准备，主线程安装 Mesh、纹理、已有地标和共享建筑 MultiMesh；一个裁剪三维 SubViewport 经预乘 Alpha TextureRect 合成到 REGION。 |

MapRelief 保留 WORLD / REGION 的 ETOPO 衍生纹理，以及当前适用的一个中尺度原生窗口和必要后继。StrategicSpatialLoader 保留既有战略/海岸分片选择和旧分片复用。LocalSpatialLoader 保留巴黎、伦敦、采尔马特、吉萨及既有交通参考的有界请求。普通相机变化没有重新三角化政治原始面。

静态银河仍由正式场景中的原 TextureRect 显示。它没有 TIME、后台任务或动态星云。R18 的 TextureRect 承载、独立二维 REGION 与裁剪 LOCAL 结构均保留。

## 2. 本轮确认并消除的重复工作

1. 原 `_on_spatial_display_changed` 把 GPU 批次安装当成相机变化。它设置相机失效，随后重新配置 WORLD 相机、同步 LOCAL 与战略地理需求，并立即申请一次目标更新。现在安装事件只使显示位置与二维缓存失效。物理水域裁切沿已安装 LOD 的键同步；目标更新由最终绘制入口申请。
2. 原战略内容完成信号同样走全部相机需求。现在标记战略内容待接入，在原绘制阶段更新对应战略层。相机仍有变化时合并到该次真实视野需求。
3. 原仅选中对象或地图外观改变时，绘制入口也调用战略分片请求。现在此分支只同步实际受选择/模式影响的行政显示需求。相机、正式历史内容刷新及重新显示地图仍更新原地理需求。
4. 原 GPU LOD 安装还发出 `place_content_ready`。可见地图资料卡会再次进入 Presenter，虽然没有新增资料事实。现在只有实际内容读取完成和行政资料完成保留资料通知。GPU 安装只更新显示。
5. 移除 `_ensure_view` 中早于最终批次提交的 WORLD `UPDATE_ONCE`；地图重新显示时也不再同时为两个目标预申请图像。隐藏的 REGION 改尺寸时不申请图像。真正的相机、外观、内容变化仍由绘制阶段更新当前目标。LOCAL 材质和图像安装所需合成请求保留；没有声称所有 UPDATE_ONCE 都是冗余。
6. LOCAL 原本在裁剪范围外也建立地形射线并遍历候选块。现在只在拾取视图已同步时，以现有实际裁剪范围排除不可能命中地形的像素。相机尚在改变时先更新姿态，不用旧范围否决缩放锚点。范围内继续使用原候选块、真实三角和水面优先规则。
7. 地表安装后，RegionView 仍常驻一份仅用于创建水域纹理的 PackedByteArray。改为安装期局部变量。RegionView 未读取的 `base_height` 接收字段及后台返回字段删除。TerrainPreparation 内部基准高度计算及真实顶点、贴地计算保留。

以上是 R21 新修改。R18 的透明混合修复、R19 的双地平线扇面、闭环邻点、后台代数/世界所属检查、旧 LOD 交接和无用 UV 清理没有改名再申报。

## 4. 4×时间推进与页面查询

正式链仍为：`0.25 秒 Timer → TimeControl.tick → advance_requested(15 × speed 分钟) → FormalWorldApplication._advance_world → SimulationStep.advance_minutes → GameClock / 各领域 → _on_world_changed`。4× 每次推进 60 分钟，单位现实时间跨过更多结算边界。

SimulationStep 中的工资、消费、生活安排、原生推进和日结、运输窗口、人物旅行、宏观小时区间、迁居、经营范围及组织日审全部保留。GameClock、SimulationStep 和领域算法文件均未修改。以下合法路径仍可能耗时，交由其工作线判断：`_economy_r1.advance_time / settle_day / dispatch_shared_window`、`_economy.settle_hour_range`、`_personal_economy.settle_due_wages / settle_due_consumption`、`_travel.advance_time`、`_responsibilities.review_settled_day`。

R18/R19 已隔离普通跨日、隐藏页面及不相关地图内容通知。本轮继续保留，没有声称普通每小时原本会重建 DEM、GLB 或全球政治 Mesh。

新确认的问题在 FormalWorldPresenter：只要人物页可见，就同时查询近期账务、物品列表、所选物品能力/消费报价、消费记录、旅行目的地与原生接管详情。多数分栏并不显示这些资料；4× 下真实人物/native 变化会反复进入此路径。

现在按现有 `PersonView.section` 查询：

- 财务摘要：现有余额/身份、生活和常住信息、首页物品、最近三笔收支。不会沿用近期账务分栏的旧分页偏移。
- 近期账务：当前账务页；不读取物品报价、消费记录和出行目的地。
- 物品与消费：当前物品页和所选物品的原能力、报价、安排等；没有所选物品时不查询详情。
- 消费记录：当前记录页及所选记录；不准备账务和物品报价。
- 岗位/订单：保留原 native、出行、岗位与经营显示查询；不附带不可见的账务、物品和消费记录列表。

原页切换继续触发刷新，打开分栏时读取当前正式数据。公共人物信息和用于岗位入口的责任信息仍读取。经济页和组织页的正式查询继续保留。没有另建 Presenter、世界状态或查询缓存服务，也没有删除操作入口。该修改只约束显示查询，不改交易、账务、消费和运输算法。

## 5. WORLD 与 R20 光照

`solar_globe.gdshaderinc`、海洋/月球/政治面太阳实现和银河资源未修改。西经 65°、北纬 20°固定入射方向、原夜面补光、定向海洋高光、月球、地球旋转均保留。没有新增海洋材质或背景。

WORLD 本轮的实际视觉改动仅为旧政治外缘作为物理海岸回退时的线色/线宽。改为与已安装物理海岸相同的 `(0.27, 0.37, 0.38, 0.64)` 和 `0.7` 像素，避免交接时另换一套墨色。本轮没有重新调整球体边缘、太阳亮度或政治旗帜色阶；不强行为版本编号改写已认可的设计。

REGION / LOCAL 仍采用制图照明，没有接入全球夜面阴影。底部黄铜机械半球仪及其几何、材质、位置、方向联动和点击实现均未修改。HUD、菜单、五槽存档和历史事实不变。

## 6. REGION 层次

保留原政治着色与地貌合成顺序。未重做政治地图风格。

- 二级以下行政线在 650—2400 米/像素间，额外从原强度渐变到 72%。原层级区分仍在。选中边界在后续覆盖此减弱，国家边界及玩家边界保持原规则。目的为给远尺度地势与国家层级留出主次。
- 中尺度原生 ETOPO 窗口原来以两轴最小边距计算过渡。现在两轴各自 smoothstep 后相乘，角部按两边覆盖共同减弱，减轻矩形角部的残差贡献。不提高地势频率，不增强对比，不改真实高程或原近景退出带。
- 海岸回退采用与已安装海岸相同的色与宽。河流中心线、原海陆差量面和水文来源不变；没有用线宽伪造河道宽度。

REGION 约 9.8 千米的全球衍生格网与四处公里级原生窗口仍有精度上限，不能由材质变成城市坡面。没有恢复 R17 删除的高度压平和重复坡度暗化。

## 7. LOCAL 地表、建筑与地标

原生地形 Shader 原来把双方向明暗权重固定为 `0.84`，经济模式也一样。现在通过原材质安装路径使用 `MapScaleStyle.relief_weight(mpp, map_mode)`，与周边地图模式一致。继续使用真实网格法线、原双方向和原 `0.84—1.12` 明暗限幅。没有新增噪声、纹理或夸大高度。

模型原单盏方向光固定在观察空间，地图转向时建筑明暗相对地理坡向改变。现在沿原地形的地理法线方向，以两方向灯的加权平均源方向转换到当前图表，再设置同一盏模型灯。灯的数量、能量、环境填充及关闭阴影的规则不变。只有实际 LOCAL 视图变化才执行。它使光照参考一致，不声称 PBR 建筑材质与制图地表像素完全相同。

巴黎 IGN、伦敦 EA、采尔马特 swissALTI3D、吉萨 Copernicus DSM 和中尺度资料保留。普通建筑的共享 GLB/MultiMesh、数量、概念性微缩布局和既有尺寸变化保留。埃菲尔铁塔、威斯敏斯特钟楼、金字塔的模型、锚点、尺寸、贴地变换没有修改。WORLD 不安装地标；REGION 继续符号；LOCAL 沿原尺度启用模型。

没有增加植物、建筑、街道、河岸或高成本特效。没有修改裁剪尺寸和像素密度，没有新增视口或第二套地形缓存。

## 8. 水文、清理和限制

保留已安装物理 LOD 同时负责填充/海岸和行政显示裁水的规则。GPU 批次完成只触发该已安装键的重新同步。没有改 LandTopology、原始 GIS、DEM/DSM、政治身份/主权/行政成员。

真正删除的是 RegionView 无读取者的高度接收字段和安装后无用途的水域字节引用，以及对应后台返回字段。没有删除仍在使用的高度基准计算、Shader 分支、法线、水域/地形精确拾取、旧有效 LOD 或材质参数。没有发现可安全整体删除的旧渲染管理器，因此未扩张清理范围。

仍缺连续河岸、水位、适用年代的河口和岸线对应，以及更多原生精细地形与垂直基准转换。Natural Earth 的海湾、小岛和中心线精度仍有限。未补造河宽、海岸、土地覆盖或随机地貌。

R20 已记载的法国西部填充/岸线不一致、巴黎地表单调及局部水文交接，本轮没有确认共同根因，也没有宣布整体修复。未从截图推断行政边界必须等于现代海岸。

仍不能从源码排序的主要负担：驱动首次 Shader 准备、GPU 目标/透明合成、主线程 Mesh 上传、复杂行政后台几何、可见经营页查询、合法日结、系统内存压力与换页。连续缩放还必须更新相机与图像。不能宣布延迟消失、少量模型成本已完全解决或风扇问题已解决。没有 FPS、CPU、GPU、内存降低比例。
