# Rust 正式世界交通

使用 `wwo-map-lab --play` 进入正式游戏。在法国开局可用下列线路验证。

## 游戏操作

- **旅行**　暂停游戏。从人物资料打开「旅行与通勤」，或点地图上的城市进入线路面板。选择鲁昂、铁路和「查询路线」。查看分段、原型票价、等候、抵达时间和风险后购票。继续计时。途中用「取消或下一站下车」结束行程，系统退还未乘区段的费用。到站后可重新购票。
- **换装**　在巴黎选择伦敦和「全部」。线路依次经过鲁昂、勒阿弗尔、勒阿弗尔港、伦敦港和伦敦。两段港口换装各需时间和运力。签证、关税和货币兑换仍待接入。
- **岗位与通勤**　到场后从「关系与工作」查看当地已知空缺并签约。法国开局的巴黎工坊是现有岗位。鲁昂当前没有可申请岗位。持有巴黎合同后可从鲁昂启用通勤。每日 06:00 按行程购票，到岗后登记，班次结束后再购票返程。工资按原发薪规则结算。暂停通勤后，已购行程仍可在下一站结束。
- **迁居**　从「关系与工作」在实际抵达、有正式人口归属的地点登记迁居。使用人口线已经合入的住户和迁移登记。常住地、通勤起点、当下地点和工作地可以不同。
- **货运**　从市场报价簿选择面包，取得报价后点击「采购货批」。在「实物货运」选货批和目的地，查询运费并确认发运。交割后获取委托销售报价并确认出售。财务和货批视图保留采购成本、运输费、收入和净收益。报价按当前游戏分钟签发，时钟推进后可重新查询。
- **存读档**　使用原生存档槽。载入后从原来的游戏分钟继续，资金、所在地、在途段、预留运力、通勤和货批一起恢复。已付客货运费按原收据恢复。人口 PR #192 写出的旧单段在途存档也可续行，旧车票没有新增扣款。

## 规则与资料

- `NativeSession.tick()` 通过 `advance_migrated_domains()` 处理发车、到站和通勤，结算与渲染解耦。同一线路的双方向共用预约。每段采用 `[出发, 到达)`，一人占一单位，货量按商品目录单位向上取整。线路容量不足时为所选路径排队。正在行进的区段履行到站承诺，后续中断时释放未使用区段并退款。
- 既有账本记录真实付款和退款。市场卖出现有库存后，货主持有唯一货批。运输中保留货权，目的地完成交割后可以远程委托出售。交割地统计市场必须有可用实收资金，才会付款并吸收一次库存。已经交割的货批可转运。MacroEconomy 的统计运输沿用自身数据和权威。
- 巴黎、鲁昂、勒阿弗尔使用同一个法国统计市场。本机面包案例的采购和售价均为 265 生丁，运费 47，净收益 −47。伦敦能接收货物，买方实收资金不足时拒绝购入，货主仍持有货批。独立城市报价与更细的商业买方待领域资料接入。
- 路线和参数沿用第一阶段的 `prototype_only` 地图数据及开发假设。法国参考铁路只用于有相应几何的路段。其他原型路径按现有端点或航线折线表达。当前没有独立历史班表或全量场站。 [交通基础与数据来源](RUST_TRANSPORT_PHASE_1.md)
- 首阶段 GLB 由现有地图网格加载器按可见实例和投影尺寸加载。既有站点与活动运输共用地图场景。远视角用线路和符号，近视角可显示轨道、列车和轮船。无运输事件时不生成车辆。远处和视野外运输继续按游戏时钟结算。

## Windows 观察

使用 1280×720 窗口、Vulkan、RTX 3050 Laptop GPU 和既有地貌。正式入口验证支付、途中存档与恢复、到达、实物货运和往返出勤。巴黎到鲁昂为 47 生丁和 169 游戏分钟，巴黎到伦敦查询为 144 生丁和 1221 游戏分钟。鲁昂通勤于 06:00 出发，08:49 到巴黎并登记两小时班次，之后回到鲁昂。

在 10 m/px 看到载客蒸汽列车和原型铁路，记录到机车、煤水车、客车与四段轨道在用。在移出视野后观察到这些模型退出驻留。静止样本约 26 FPS，CPU 绘制 2.7 ms。区域内运行约 25 FPS，CPU 绘制 3.5 ms。静止三秒采样的整游戏工作集约 410 MiB、独显专用约 561 MiB、进程 CPU 约占全机 0.7%，独显 3D 引擎瞬时约 7%。无同条件基线，交通独立增量和帧时间分位 `NOT_RUN`。镜头内的实际轮船、近景高 LOD 的实机核对与全球巡视 `NOT_RUN`。
