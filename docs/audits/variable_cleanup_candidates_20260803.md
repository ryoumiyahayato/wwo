## 组 3：需要产品规则后才能决定

### 正式玩家身份

需要明确以下哪一个是正式产品的权威身份，以及它们如何映射：

- `GameSessionService.player_character`：核心会话对象。
- `CharacterRosterService.player_character_id`：人物目录稳定 ID。
- `holographic_workspace_runtime.active_character_key`：UI 档案键。
- `selected_country_id`：地图选择；核心 v1 存档中的同名键则表示玩家所属国家兼容字段。

在规则确定前，不合并、不改名，也不让 UI 选择反向修改权威人物。

### 法理归属与实际控制

历史政治数据只有 `controller_id`，UI 又把它投影为 `sovereign_id`。需要产品定义至少回答：殖民地、保护国、租借地、占领区、共主关系和无单一控制者怎样表达；法理归属是否随时间变化；存档是否保存源数据版本或实际控制增量。没有规则前，不引入名义上独立但始终同值的第二字段。

### 正式事件、消息与可见性

需要定义事件由模拟、资料库还是 UI 产生；哪些事件对玩家可见；未读状态是本地 UI 状态还是存档状态；事件 ID、时间、主体和地理定位的稳定性。定义完成后再决定复用 `WorldActivityService`、V2.3 消息账本或建立正式专用服务。

### 正式经济 owner 粒度

当前正式经济是 50 个经济体的宏观聚合。若产品要加入企业、家庭、政府、运输商和组织账户，需要先定义复式/单式记账、资产负债、所有权、破产和跨日结算顺序；不能直接复制 Alpha/V2.x 的同名余额，也不能把当前 `country_states` 判作重复。

## 组 4：明确保留

| 状态组 | 保留理由 |
|---|---|
| `total_minutes`、`_minute_remainder`、`total_hour` | 一个权威累计分钟和两个只读派生视图；关系已由恢复校验约束 |
| `economy_polity_ids` / `economy_by_polity_id` | 正向和反向查询方向不同，避免热路径反复扫描 |
| `_crosswalk_records` | 载入期历史映射源缓存，用于解析多政治单元经济体 |
| `selected_*` / `hover_*` / `active_*` | 生命周期、交互阶段或主体不同；前缀是语义，不是噪声 |
| `player_character` / `player_character_id` | 对象引用与稳定目录 ID 的职责不同 |
| `country_states` / `polity_records` | 50 个高细节经济体与 151 个历史政治单元是不同粒度 |
| `routes` / `shipments` / `history` | 路网定义、在途对象和有界历史不是同一状态 |
| AlphaHistoricalWorldEconomyData 的 16 个成员 | 正式经济实际实例化该类，不能按目录名判为不可达 |
| V2.2/V2.3/Alpha 存档与夹具 | 属于版本/隔离产品线兼容边界，未经入口与迁移证明不得删除 |

## 组 5：证据不足、保持观察

- 8,261 个动态调用词法候选、84 个动态资源路径、63 个 NodePath 和 271 个信号候选不能由简单全局搜索穷尽解析。
- 135 个同名跨 owner 分组可能只是常见领域名；62 个近名分组可能由 `current/selected/active/player` 编码必要差异。
- 302 个 F 成员主要位于 Alpha、V2.2 兼容或隔离产品线。F 只表示当前正式入口未命中；编辑器场景、外部脚本、未来迁移或专用验证仍可能使用。
- 正式产品没有确认的权威 AI 入口，但其他产品线 AI 状态可能仍有独立测试与演示价值。
- 缓存和索引只有在真实构建、失效和性能证据齐全时才能评估移除；名称包含 `cache/index/lookup` 不是充分条件。

## 建议的最小后续批次

以下批次互相独立，均应从新的集成 Base 开始。每批只解决一个状态边界。

### 批次 A：正式日结恢复一致性

- 目标：证明并约束 `_last_day_index` 与权威时间的关系。
- 允许范围：正式经济恢复校验、专用存档夹具和时间/经济回归。
- 禁止：顺便修改经济公式、商品参数、运输算法或 UI。
- 必测：合法旧 schema、未来/过去 day index、23:59/24:00、多日跳步、恢复失败完整回滚。
- 回滚：保持现有字段和 schema；若派生方案失败，只增加拒绝不一致快照的校验。
- 完成条件：跨种子结果不变，合法存档往返，篡改存档确定失败且内存状态不变。

### 批次 B：正式存档原子写入

- 目标：让 `formal_world_1900.json` 写入具备临时文件、校验和可恢复备份语义。
- 允许范围：正式存档适配层及其测试；优先复用 `AtomicJsonFileStore`。
- 禁止：改变正式 schema 字段含义、路径或经济内容。
- 必测：写入中断模拟、主文件损坏、备份恢复、无权限/磁盘错误、旧文件读取。
- 回滚：保留旧读取路径；写入适配可独立撤回。
- 完成条件：失败不破坏上一份可用存档，旧存档仍可加载。

### 批次 C：玩家身份提交边界

- 目标：定义一个经过人物状态重验的权威玩家切换/恢复入口。
- 允许范围：`GameSessionService`、继承事务、存档恢复及定向回归。
- 禁止：把地图选择或 `active_character_key` 自动当作玩家身份。
- 必测：正常继承、回滚、退休、死亡、长期监禁、失势、损坏存档、活跃人物上限、AI 覆盖和双向索引。
- 回滚：保留现有直接提交顺序作为兼容实现，先加入口再迁移调用点。
- 完成条件：所有权威规则在服务边界重验，失败时对象和 roster ID 一致回滚。

### 批次 D：正式事件权威化

- 前置：产品规则明确事件来源、可见性、未读和存档语义。
- 目标：把正式模拟事件与 UI 投影分开。
- 允许范围：一个正式事件服务、适配投影、专用存档/旅程测试。
- 禁止：直接把 V2.2/V2.3/Alpha schema 拼接进正式产品。
- 必测：ID 唯一、时间单调、主体有效、上限、存档往返、选择/定位、已读行为。
- 回滚：UI 可继续读取适配后的相同展示字典；不在同批删除旧字段。
- 完成条件：正式 UI 不再自行制造模拟事实，展示状态仍由 UI 持有。

### 批次 E：法理与控制模型

- 前置：殖民/保护/占领等产品规则与 1900 数据来源确认。
- 目标：若规则要求，建立独立法理 owner 和实际 controller，并提供日期与迁移。
- 允许范围：历史数据 schema、加载校验、地图投影、存档版本和定向测试。
- 禁止：仅复制 `controller_id` 到新字段后声称已分离。
- 必测：独立国家、殖民地、保护国、占领区、无 controller、跨日期、旧存档迁移。
- 回滚：旧 `controller_id` 读取保持兼容，投影可回退。
- 完成条件：两个字段在至少一个合法案例中可不同，并由规则/数据验证。

### 批次 F：Alpha 历史数据命名边界

- 目标：让正式依赖的历史经济数据和商品目录具有明确共享身份。
- 允许范围：资源/类名适配、路径兼容和入口测试。
- 禁止：删除 Alpha 产品线或同时改经济数值。
- 必测：正式世界初始化、50 个经济体/151 个政治单元不变量、旧资源路径兼容。
- 回滚：保留旧路径常量或重定向适配。
- 完成条件：正式入口不再被目录名误判为隔离，同时历史数据内容不变。

## 每批共同门槛

1. 固定并记录新的 Base、分支和干净状态。
2. 先写失败测试，再改最小生产代码。
3. 按修改范围运行统一验证和 Codex 审计回归；动态验证不得污染主审计 worktree。
4. 涉及存档时保留旧 fixture 并验证往返、损坏拒绝和失败回滚。
5. 涉及权威人物/组织/行动时运行状态一致性回归。
6. 涉及 UI 时完成 1280×720 人工旅程；涉及模拟公式时重新建立性能基线。
7. 每个批次独立提交、独立 Draft PR，可单独撤回。
