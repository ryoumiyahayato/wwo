# 连续算法规格

以下模型是明确的第一版实现选择。数值参数进入版本化 JSON 配置，标注 `simulation_assumption`，并接受敏感性测试；不要当成已验证的历史规律。每节编号可直接用于测试和任务引用。

## A01. 共享资源分配

输入是同一个窗口的全部 `Demand(request_id, actor_id, resource_key, amount, priority_class)`。有效需求必须已有资金/身份/前序条件；不能通过虚报无支付能力的需求抢占资源。

同一资源先按明确制度优先级处理，再在同级按有效需求量比例进行 R02 的封顶最大余数分配。没有特别规则时所有主体同级。ID 只决定不足一个 quantum 的余数归属。优先权必须引用有效授权记录；不得根据字符串以 military 开头就自动优先。

```text
allocate(C, demands):
  remaining = C
  for priority in sorted_priority_classes:
    group = eligible demands at this priority
    Q = min(remaining, sum(group.amount))
    give = capped_largest_remainder(Q, weights=group.amount, caps=group.amount)
    remaining -= sum(give)
  return exact integer allocations
```

同资源有 60、60 两份同级需求，容量 100，得到 50、50；无论 Economy/Military 提交先后和字典插入顺序如何。如果其中一份合法高优先级，得到 60、40。容量为零全部排队。需求 1、1、1，容量 2，按稳定 ID 给前两项各 1。

一个生产批次需要多项资源时**不能独立分配后直接拿最小值就算完**，否则占用用不掉的煤或工时。第一版采用有界、确定的两步：先计算 A04 中完整可行批次数，再按“已承诺合同到期日、计划创建时间、site_id”排序，逐个为完整批次原子保留全部投入；不足一个完整批次不保留任何投入。普通库存/运力用比例公平；组合资源采用这一明确的可解释排程。它不是全局最优排产，延期可触发下轮改计划。

所有退款、撤单释放只影响未来可用部分；同一相位最多再分配一次释放量，剩余进入下一窗口。不能在当前边界无限寻优。

## A02. 人口、劳动和具名人物

### 劳动分配

每个地点的工作年龄人口映射到互斥 labor pools：`available、employed、military_service、training、unable`。`employed` 内的罢工是可供劳时减少，不能同时把同一批人计成 unemployed。多个短工分配以人分钟预算核验，不能超过群体人数×本期可工作分钟。

日界形成雇主 vacancies，条件含技能、地点、班次、薪资、通勤时长、已预留工资或合法赊欠额度。求职群体从本地/实际可达岗位索引取最多 8 个候选，按以下净价值降序投递：

`net_wage = offered_pay − commute_cost − expected_unpaid_pay`。

同工资先按通勤时间短、岗位 ID 排序；雇主在满足资格的申请内按技能高、请求时间早、cohort_id 排序录用，最多处理固定 3 轮。未匹配进入下个日界，不丢申请。普通 NPC 不搜索全球所有公司。玩家指定自己能知道/到达的岗位时不受候选截断限制，但使用同一录用与工资规则。

录用事务一次减少 available、增加 employment allocation、建立工资合同和班次。产出不得先发生再反推工人。工资每工作一分钟应计，按合同 pay_due_time 到期；失能、服役和迁移先处理原班次未来部分。迁移占用交通和路费，到达后才进入目标劳动力池。

### 人口流量

月结算继续用现有 MacroPopulation 的年龄与迁移余数。出生/自然死亡率由 scenario 参数按既定年龄桶生成，死亡先分配到具体人口子集，不能减总人口后任由劳动分配超额。战斗/事故已有 casualty_id 的死者从当月自然死亡风险池排除；所有死亡最终走统一人口转移。

原有三个边际不提供职业×宗教×年龄的联合分布。第一次需要新维度时采用明确的估计拆分规则并保存，不每轮重生成。空缺估计与历史来源分开记录。

### 具名化

具名人物是同一个 cohort 中的独立覆盖条目。`named_count + anonymous_count = cohort_count`。展开一名工人时：anonymous−1、named+1；划出其劳动配额、消费份额、账户份额和已有合法合同引用。总人口不变。若没有可切分合同，就暂不允许从该集合抽取，返回具体冲突。

例如总人口 1000、其中劳动 cohort 600，展开 1 名已就业者后劳动 cohort 仍 600，匿名就业人数少 1，具名就业覆盖多 1。他的死亡令总人口和 cohort 各少 1，不能仅删 Person；也不能死亡后又在匿名损失中扣一次。

第一版不因镜头反复合并/展开，具名后保留身份；聚合 sector pool 同理。复杂度依赖聚合格和有限具名人物，不是所有自然人。

## A03. 财务循环：应计、支付和预算

每笔普通货币转移 `transfer(payer,payee,currency,n)`：检查 n≥0、同币种、payer 可支配余额≥n、账户状态、授权和幂等；借方余额−n，收方+n。同一交易不允许两次扣款。发行与销毁另有有权限的操作，不能复用 transfer。

`available = balance − active_holds`。hold 是余额子集。预算使用 `approved、committed_unpaid、paid`：`new_commitment ≤ approved − committed_unpaid − paid`，同时需要真实现金或融资；支付将 committed_unpaid 减少、paid 增加，不再次消耗预算。撤销未履行部分可释放承诺；已履行的欠款不能删掉。

工资到期先建立 `Claim(debtor,creditor,principal,due,cause)`。现金不足时支付可付部分并保留 remainder；债务顺位相同按应付比例分配。工资税若规定代扣，则雇主本次支付分成净工资与税两项，和等于实付毛工资，未支付工资上的纳税时点按具体 tax_rule 配置。

生产、工资、运费、利息与补助必须最终连到某个账户。群体消费池是群众的聚合账户；没有具名家庭也能真实买不起食物。政府账户不得用国家 income_index 代替。

### 数值闭环 T06

独立测试场景初始现金：企业 1000、居民池 100、政府 100，总计 1200。企业完成 80 毛工资劳动，10% 实付工资税代扣：企业 920、居民 172、政府 108。居民随后以每份 10 买入 6 份本地面包并消费：企业 980、居民 112、政府 108，总计仍 1200。企业库存减少 6，居民消费流量增加 6。

若雇主只能支付 50，则实付工资税 5、净工资 45、工资欠款 30。不能把居民可消费金额按完整工资 80 增加。

## A04. 生产、库存、维护和投资

每个 site 持有配置：operator、place、recipe、installed_batches_per_hour、labor_minutes_per_batch、machine_minutes_per_batch、condition_bp。每个配方明确输入/输出/时长；矿山和农业可以把土地、矿藏、季节可采量作为原始资源池，不能把它们与无输入无限工业生产混为一谈。

计划批次：

`need_output = max(0, firm_orders + target_stock − own_available_output − incoming_committed_output)`。

`planned = ceil(need_output / output_per_batch)`，多输出配方以主产品需求排产，副产品真实入库，满仓需占用输出仓容或推迟生产。

可行批次：

`b = min(planned, machine_limit, labor_limit, min_j floor(available_input_j/input_j_per_batch), output_storage_limit)`。

machine_limit 和 labor_limit 从实际分配的机器分钟和劳动分钟计算。批次开始原子保留投入、劳动、机器和输出仓容；输入移到该过程的 WIP 保管状态，不再被市场出售。按配方持续时间完成时，WIP 记入工业消耗并增加输出。取消时按配方声明的可回收比例返还原料，剩余记损失；不能无成本瞬间取消已生产一半的炮弹。

一个批次需要 10 面粉、5 水、2 劳动小时、1 机器批次，产出 10 面包。计划 3、面粉25、水12、劳动3小时、机器2批次时，只能开 1 批；结束面粉15、水7、面包+10、劳动使用2小时。原料不能先给每台工厂完整计划额度然后产生负库存。

A04 有显式生产时长，所以同一小时不会让矿石→钢→炮弹整个链按数组顺序瞬间流过。完成输出可在后续边界启动下游，改变遍历顺序不改变产量。

磨损按实际机器分钟扣减 condition，并保留整数余数；condition 对可用机器时间产生明确约束。维修过程占机器、工人、材料和付款，到完成才恢复 condition。投资创建建设过程，消耗施工材料/劳时，安装完成才增加产能；研究配方必须先改造和培训才能使用。

库存过量不能靠强制删除到 target_stock 修复；超仓阻止新批次/进货或触发有记录的丢弃/变卖。真实腐败和损坏按商品速率，逐库存记录损失和余数。

## A05. 有支付能力的市场

第一版使用**日界统一挂牌价 + 有资金的批量成交 + 次日价格调整**。它是离散市场模型，避免每轮反复求全世界均衡。价格不是由政府预算需求直接推高。

### 消费需求和预算

cohort 需要表按每人每日量计算，先生存食物，再燃料/住房等必需，再可选消费。需求按需要类别分组；类别内部先用标准篮子份额分预算，不让商品 ID 字母顺序决定谁总能买到东西。

```text
desired_q[g] = people * per_person_need[g] + bounded_backlog[g]
spending_cap = min(available_cash, planned_daily_spend)
budget_by_category = fill_need_categories_in_declared_priority(spending_cap)
budget[g] = capped_largest_remainder(category_budget, basket_weights, desired_q[g]*price[g])
funded_q[g] = min(desired_q[g], floor(budget[g]/price[g]))
```

backlog 只保留可补偿的需求。昨天没吃的热量不会无限形成明天买几百顿饭的订单；食品 backlog 默认 0，缺食进入营养压力状态。耐用品需求可累计到配置上限。

生活状态看 `consumed/required`，现金约束看 `funded/desired`，供应约束看 `delivered/funded`，三者分别输出。只有实际消费改善营养；在途食物不算吃到。

### 本地现货成交

输入：当前价 P、报价≤P 的卖方未保留库存、限价≥P 且已预留现金的买方数量。自己既供又需同种商品先在 owner 内净额处理，内部用途真实转移/消耗，不洗出交易量。

`Q=min(sum(eligible_supply),sum(funded_demand))`。分别按买方需求和卖方可售量分配 Q，稳定 ID 排序后做双指针配对。每笔成交将卖方库存所有权转给买方、买方 escrow 付给卖方；税费另列，买方 affordability 含税费，不能成交后透支。已成交但未消费的货留在买方库存。

库存 10，价10，买方原需求8和8、各有80现金：成交各5、各花50，未用预留各释放30。卖方收到100，总货量未改变；消费另记。

不在同一可交付地点的买卖创建 A06 运单；卖家发货不代表居民已消费。进口补货由当地商人/sector operator 下单并承担资金和在途风险，不把所有居民变成全球采购者。

住房/医疗/授课等 capacity_service 使用同一资金约束生成服务预约，供给来自实际设施与劳动容量。相应时段服务交付后确认满足量和费用，不执行库存转移/腐败/货运；租住面积不能因为市场日结又被同一时段卖给第二个住户。

### 次日价格

使用**本日已融资需求 D、合格可售量 S**，不包括没钱的愿望。整数不平衡：

`z_bp = trunc((D−S)*10000 / max(1,D+S))`。

`delta_bp = clamp(trunc(z_bp/10),−500,+500)`。

`P_next=max(1,round_half_up(P*(10000+delta_bp)/10000))`。

实际实现为上式加持久 `price_carry`：`raw=P*(10000+delta_bp)+carry`，`next=floor((raw+5000)/10000)`，`carry=raw−next*10000`。若 next<1 则钳到1并清除继续压低价格的余数。初始 carry=0。这样低面值价格长期受压仍能移动，不会因每次舍入永远停在1；例中的105不变。

无买无卖 D=S=0 时价格不变，并标记 no_trade，不假造“市场稳定”。D=150、S=50、P=100，得到 z=5000、delta=500、P_next=105。D=S=100 时价格不变。涨幅上限只是单日调整速度，不是永远锁在 base_price 上下；缺货不会被价格上限自动解决。

多个商品价格只影响下一轮需求/生产计划，不能在同一相位循环迭代到任意收敛。高通胀、供给崩溃和投机需要作为仿真结果诊断，不能直接 clamp 产出使测试变绿。

## A06. 运输、交付与实际地理

运输输入：真实货物预留、起终点、可用承运组织、付款/合同、货物 LU 换算、截止时间。Dijkstra 在已有可通行图上按 `travel_minutes + expected_queue_minutes + fee_equivalent_minutes` 估价，边权非负；ties 用 link_id。跨境许可、占领和关卡作用于实际边。最多保留 3 条可用候选路径，路线失效只更新依赖这条边的运输。

**容量语义固定**：线路额度是每小时进入路段的载荷吞吐；列车/车队/船舶则另有载荷和占用时间约束。不能用同一数既表示“每小时通行量”又表示“整个旅行同时在途量”。现有默认数值须经场景换算标注，未校准只是模拟假设。

每次只申请下一路段，不同时占住尚未到达的全部线路。等待下一路段的货物停在中转仓或运输保管状态。这样无需做全图多资源死锁检测。仓储和装卸能力也需要实际保留；没有中转容纳空间时不能发入。

货可拆成载荷 quantum 的 tranche；每份 tranche 有相同 parent_order、独立数量与位置。为压缩记录，可合并同 owner/商品/地点/ETA/条款的份额，但不得合并导致交付时间或债务丢失。

```text
收集全世界本窗口下一路段请求
→ Spatial 一次 finalize，冻结分配版本
→ Economy/Military/Travel 全部读取同一 allocation_id
→ 扣发货方在仓量，增加在途量，付已到期运费
→ 到 route ETA 才移入下个节点
→ 到最终地点才形成收货和尾款结算
```

发货前钱/货/载荷任一失败，全部不变；发货后被劫或损失是新的真实事务，不能回滚旅行。默认商品所有权在发运时转给买方，买方承担运输风险；合同明确约定由卖方承担时，所有权到收货才转移，并在 escrow 留款。两种模式都必须有 payload 字段，不能由不同领域自行解释。

当交期已过但路线仍可行：订单变 overdue，继续履行并按合同累计赔偿义务，不删除。没有路线则 blocked，订阅 topology revision。跨窗口不清除运单本身，只清本窗口申请。

## A07. 企业、个人与机构怎样决定下一步

NPC 使用**有限候选的确定性滚动规划**。不用大语言模型，不做全世界多步搜索，也不让 Organization 内出现万能 `think_world`。

每个控制岗位/个人有 `goal_id、next_review、current_plan、decision_index、known_facts`。权限由实际任命/个人资格提供，经济账提供约束，Knowledge 提供观察。生成、评估、执行是三层：

1. 从本地索引生成最多 8 个可用候选，每个候选列出会消耗的资源和预计结果；WAIT 永远是合法候选。
2. 将每个候选复制到仅涉及本主体和直接对手的预测数据，使用与执行同一个报价/配方函数预测未来 7 日；未知对手行为保持上次已知计划，不能读取未来。
3. 硬约束不满足的候选淘汰；剩余按本角色评分最高者执行。收益相同按切换成本低、candidate_id 小排序。当前计划已可行且提升不足 5% 时保持计划，防止每天来回改。
4. 只提交命令；是否成功以实际结算为准。失败记录 limiting_resource，下一复查生成针对性替代方案；不能直接执行预测的收益。

角色评分不是一个全国 influence 值，各自有可计算对象：

| 决策者 | 有限候选 | 选择规则（按从左到右的字典序，不同量纲不乱加） |
|---|---|---|
| 普通人/cohort | 求职、现工作、培训、迁居、加入活动、等待 | 先减少未来3日生存缺口；再提高7日净收入；再减少风险与通勤 |
| 企业经营者 | 产量档0/25/50/75/100%、供应商候选、借款、维修 | 先避免到期现金违约；再减少已签交付缺口；再最大化7日现金净额；同值少切换 |
| 军事指挥者 | 守、移、攻、补、撤，各从邻接目标/现任务生成 | 先满足不可违抗的有效命令；再按任务达成预计值；再减少伤亡和断供风险 |
| 行政机构 | 已收到任务按期限与法定紧急级排序 | 先处理到期法定义务；同级先覆盖实际未服务人数；成本不足进入队列 |
| 工会 | 等待、谈判、有限罢工、停止罢工 | 先保障成员基金可持续天数；再比较成员可实现工资改善减停工收入损失 |
| 政党 | 有资格的提案、结盟、宣传、提名 | 先满足组织生存/期限；再增加预计有效席位或任命支持；再降低资金成本 |
| 银行 | 审批、拒绝、展期、追偿 | 满足流动性/资本约束后，按预期净利排序；违约债权按合同保障优先处理 |

默认企业 7 日预测期、3 日安全现金、7 日安全原料；这些初值属于平衡参数。银行和工会用下节具体判据；军事战斗预测用 A11 的同一公式。没有对应规则的候选不显示也不伪执行。人可以主动改变目标，不能突破物理资源和授权。

一位玩家当部长时，只替换这位人物的决策输入。其他职位、工厂和居民继续运行，不把全国主体 AI 停掉。

实现候选预测时必须固定以下量，不能留下“AI自行判断”的洞：企业 `cash7=opening_available+已知应收可付额+按保守已知日销量估算收入−计划投入−工资−税−债务到期额`，无信用记录的应收预测按0；军事 `mission_value` 从显式目标控制权/抵达截止时刻计0或10000，`loss_cost` 用A11在最近已知敌情上的伤亡预测，未知区域加配置侦察风险，不能使用对方实时精确状态；政府 `coverage` 是任务完成的去重人数；政党 `seat_gain` 用当前已知支持与A09相同席位算法预测，不凭空推测对手下一步。

普通人技能成长绑定真实学习/实践劳时。每个可训练任务给出 `effective_minutes_required` 与 prepare/cost 条件；确定性要求达到上界时，成功概率必须为10000bp。低于上界才使用有种子的技能检定。任职仍需空缺和制度程序，熟练度本身不创建职位。测试要分别验证“个人有保证完成其训练任务的路径”和“不能保证竞选/商业竞争结果”，不能把前者错误扩成所有世界行为必胜。

## A08. 银行、贷款与破产

按货币区配置结算资产及兑换规则；第一版各区内贷款/支付闭环，跨货币交易必须有兑换账户和真实可用外汇，缺配置明确不成交。现代银行资料只用于账务恒等式，不自动给 1900 所有地区同一法制。

金融记录至少区分：客户结算余额、银行存款负债、银行准备资产、银行贷款资产、银行资本、借款人贷款负债。客户余额是银行负债的明细，不能把它和银行负债加成两份钱。

### 批准算法

以借款人最近30日真实收入/支出和已签订单计算：

`cashflow = receipts − operating_payments − existing_debt_service`；`debt_service_capacity=max(0,cashflow)`。

`new_period_service ≤ floor(debt_service_capacity*10000/coverage_required_bp)`，默认 coverage_required_bp=12500。

再检查抵押折扣价值、债务集中度、放贷后资本/风险资产≥配置下限，以及预计跨行支出后的可用准备资产≥流动性下限。没有历史的主体只接受明确担保/抵押型产品，不能把未知利润填为无限。

### 账务动作

同银行发放1000存款贷款：银行贷款资产+1000、存款负债+1000；借款人存款资产+1000、贷款负债+1000。准备金不自动增加。实际跨行付款600：付款人存款−600，银行A存款负债−600/准备资产−600；银行B准备资产+600/收款人存款负债+600。没有可用准备则排队或先取得有真实对手的同业贷款。

偿还本金200：贷款资产、借款人债务、客户存款和银行存款负债各减少200。利息20单列为银行收益/借款人费用；不能用“本金+利息”一起减少本金。利息按合约日数基准和旧本金积分并保留余数；不默认所有国家相同的365天约定。

不提供存款创造的私人借贷产品则是贷方余额−n、借方+n及相等债权债务，两种类型不得混用。

### 违约与清算

到期未付→宽限期→重组提案→被拒或届满进入清算。清算先冻结新承诺，继续保存现有库存/人员/债权；按制度顺位出售资产，所得分配给债权人，剩余负债记已核销。抵押资产不能同时担保超过登记许可的金额。银行坏账减贷款资产和资本；不能直接删公司让银行资产消失而不承认损失。

## A09. 群体感受、媒体、工会与政党

政治不禁止数值，但每个数必须有对象和来源。每个 cohort 保留小型 issue 向量、对有限相关组织的支持、消息来源信任。只维护实际触达的关系边和主要候选，避免全人物关系矩阵。

### 感受更新

以本人消费和收入账直接可知的事实计算：

`food_gap_bp = 10000 − min(10000,consumed_food*10000/required_food)`；无需求时取0。

`arrears_bp=min(10000,unpaid_due_wages*10000/max(1,contracted_due_wages))`。

日目标压力 `target=(6*food_gap_bp+4*arrears_bp)/10`（整数截断），EMA `stress_next=stress+trunc((target−stress)/7)`，保存舍入余数防止长期偏差。短期 shock 不直接扣政党支持，而通过归责与政策匹配影响下一步。

媒体报告包含 fact_id/claim、source_org、target_audience、发送/到达时间、reach人数、可信度、立场；媒体能发布错误 claim，但世界事实不改。发布占纸张/印刷/记者劳时与分发费用。每个受众按已触达人数比例和来源信任更新 belief：`belief += trunc(reach_bp*trust_bp*(claim−belief)/10000^2)`，分次刊发次数和余数按期次保存，禁止每次打开消息反复加支持。

例如 belief2000，覆盖50%、信任80%、claim8000，一次期次后 belief4400。未到达信息不能先改变政治判断。本人欠薪是本人可直接观测，不要求等全国媒体报道。

### 支持形成与选举

各组织对有限议题有公开政策 position；cohort 的匹配度为加权绝对距离的反向值。组织具体绩效来自已知工资、救济、征税、失业、战事等带 cause_id 的结果，归责表决定雇主/地方政府/中央等权重，和≤10000，不能每个都承担完整一份。

原始偏好 `v_p=max(0, base_affinity + policy_match + known_performance − known_cost)`。配置明确这四项各取−10000..10000，均为模型得分。加入 abstain 选项，按最大余数归一为10000支持点。各组织的互斥投票份额必须相加到10000；工会会员和政党支持可以重叠，不当作两个投票人口。

选举程序：资格/选区规则→提名截止→campaign过程→投票截止→按合格且动员的真实人数分票→按制度分配席位→组阁/任命。每个选区人数来自去重的 cohort 投票分配；只在截止边界冻结票数。本版为配置为比例代表的选区选用 Hamilton 席位算法，100票中 A60/B40、5席得到3/2；单席制采用最高票、同票按配置的决选程序，不能偷用比例代表。

君主任命、议会选举、党内会议分别有 procedure type。只实现了某 procedure 的国家可以运作该机制；缺的制度不能用随机换总统假装完成。换政府必须原子结束旧任命、建立新任命，财政账户和国家人口不因此重置。

### 工会谈判与罢工

成员登记由 Organization，劳动影响通过 Labor。谈判命令提供 wage_request、期限、涉及 employment_refs。雇主比较接受工资后的7日可行现金与拒绝后的停工预测，按 A07 做选择。到期拒绝后有表决资格者按其工资缺口、家庭可支撑天数和基金保障选择赞成/反对；固定简单版赞成条件：`requested_net_gain_over_7_days > expected_income_loss` 且基金+储蓄能覆盖预定停工日数，玩家可自主投票。

表决超过规则门槛后，`striking_people=已登记赞成人数中实际愿意参与者`，从下一班次有效劳动中扣除，并生成每日救济支付。100雇员中40罢工，正常每日8小时，未来有效劳动为480人小时；不能直接写 factory_efficiency=0.6 后仍付800工时工资。

基金不足以支付下一日承诺时重议/减少救济/结束罢工由决策产生。政府禁令只形成执法任务，不能自动把 labor strike 清零。

## A10. 政府规则和行政执行

`Rule` 必有 issuer、适用辖区、对象、行为、开始/结束时间、procedure_id、执行机构、费用/补偿条款。Organization 负责谁任职，Institution 负责该职位在此规则下可做什么；两个条件都满足才是合法行政命令。

立法按 procedure 完成才写新 rule_version；税率变化影响生效后交易/应计。税基来自明确账项，如工资实付、销售额或利润，不能三者混用；具体税率和征管制度在国家配置，不硬编码到公式。

行政服务是有劳动和资源的队列：`tasks_capacity=floor(allocated_staff_minutes/minutes_per_case)`；按法定紧急级、到期时间、case_id 执行。100件事务、可用600行政分钟、每件10分钟，本轮执行60件，40件保留原 ID。未办完就是未办完，不能套 capacity_index 宣称都实施了。

征用：核验范围→实际清点/执行→库存/车辆占用转移→创建补偿债务。法律存在但没有执行人员时，只有待执行任务；财产不转移。地方控制变化改执行可达性，不自动改法定所有权。

救济：先由预算承诺和国库出资，按 eligible people 的缺口分配真实金额/物资，再影响其消费和评价。政府自己也会因财政不足而欠付，不靠 political_power 生成食物。

地区控制统一由 Spatial 内明确的 TerritorialControlLedger 接口写；Military 的旧 region_controls 改为查询。行政/军控/主权分别记录，战胜不会自动合法吞并。区域规则映射需由现有几何 crosswalk 指定，不能夺一个城市就默认整个国家改色。

## A11. 军事补给与持续交战

建部队事务从 Labor 的适格可用集合划出人员，分配经济库存中的装备。`formation.personnel` 是分配的派生视图；不能调用 create_formation(10000) 平白增加1万人。待命部队仍按日吃饭/领薪/维护；军需需求经有权限且有预算的组织转成订单。

部队物资存在 StockLedger 的 formation custody。先消费真实到达物资，再计算可执行训练/火力。删除正式入口的 set_supply_input 无限源；仅保留命名明确的测试种子工具。路线与运力沿用 A06，军队没有独立 transport_capacity 商品来替代真实铁路额度。

### 接敌和参战分配

按相邻控制单元和当前任务建立 engagement；每个 formation 对所有 engagement 的人员、装备、弹药分配总和不得超过可用。第一版接敌时段固定15分钟，援军、撤退、死亡、资源耗尽等更早边界可以切短；镜头无影响。

为每种武器定义 `ammo_per_shot、shots_per_gun_minute、losses_per_shot_bp、target_exposure_bp、suppression_gain`。步兵近战单独定义接触所需距离与人员分钟，不能无弹药时继续使用同一种远程火力。

区间长度 Δ：

`desired_shots = integrated(active_guns * shots_rate, Δ)`。

`actual_shots=min(desired_shots, floor(allocated_ammo/ammo_per_shot))`。

`expected_loss_numerator = actual_shots * losses_per_shot_bp * target_exposure_bp + casualty_carry`。

`losses,carry=divmod(expected_loss_numerator,10000^2)`，losses 封顶于分配的敌方可受损人数。超过现存目标的火力仍消耗弹药，不能把多余伤亡余数带给下一支新到的敌军；封顶时该目标损失 carry 清零。多方攻击同一目标时先合计损失并封顶，再按各自火力分配归因，不能依遍历顺序各杀一遍。

**同时结算**双方区间起始兵力和火力，再一次提交弹药、伤亡、压制。损失中的死/伤比例来自已标注的武器/环境参数，用最大余数分配；伤员进入医疗过程，战死进入统一人口/人物事务。士气、疲劳等只作用于下一段明确的射速、暴露或撤退判断，不能凭综合 power 一次裁定胜负。

例：一个15分钟段，期望射击100次但弹药只有60，单次损失率500bp、目标暴露10000bp，实际射击60、弹药消耗60、损失3。两个方向都用区间开始状态计算，不能因为先更新一方伤亡就降低其已发生的还击。

### 撤退和控制

连续两个交战段组织状态低于规则阈值，或命令撤退且有可达出口，建立撤退移动过程。撤退途中仍可能受损；到达安全节点后结束 engagement。没有出口时按 surrender 程序处理，人员进入被俘分配，不等同死亡。

一方无在场可战人员/完成撤离，另一方完成驻留确认过程后提交**对应控制单元**军控变更。新控制影响未来交通与行政任务，再由这些事实影响经济和政治。宣战的授权、外交状态与开火指令是另一前置条件；和平世界不会仅因地图边界接近而自动开战。

医护按 `min(实际医护劳时/每人所需劳时,药品,床位)` 分配治疗；伤员按病情和等待时间进入有限队列，恢复后退回可用分配。玩家救助同样消耗其中的药、劳时和床位，不另存个人战斗世界。

## A12. 其他组织使用哪些具体算法

这些内容不通过“新增一种 organization_kind”即完成，而各有明确过程。

| 内容 | 输入和算法 | 输出与失败 |
|---|---|---|
| 学校/培训 | `seats=min(设施席位,教师分钟/每席需求,出资席位)`；报名按资格、申请时间分配；占学员时间 | 完成规定有效学习分钟并通过配置考核才增加技能/资格；缺经费暂停，已学进度保留 |
| 研究 | 按研究人员实际技能加权劳时累计 progress；材料/经费不足速率为0；达到 threshold 后产出可采用 recipe_version | 不给全国加效率；企业通过A04改造采用；失败/取消不追回已经花的物资 |
| 慈善/教会救济 | 捐款转账，实物入库，按已登记受助人数×缺口比例分配 | 到达并消费才减少缺口；工作人员也占劳动，组织无库存时不能继续发粮 |
| 地方势力/地主 | 拥有土地/租赁合同，租金由Finance到期；庇护和调解使用行政/服务队列 | 影响实际就业、租金、案件与支持；不能直接写整省忠诚 |
| 犯罪/走私 | 独立非法移动/夺取过程，使用实际人员与路线；途经检查节点按 inspect_capacity 分配受检量 | 发现时创建案件/扣押；未查到实际货物可继续；目标库存减多少，犯罪方/扣押仓增加多少 |
| 执法/司法 | 案件证据和管辖→调查劳时→裁决程序→执行劳时/拘押容量 | 未执行判决不自动扣资产或抓人；罚金转账、伤亡/拘押走同一人物分配 |

侦测若需随机，采用 R08 的独立确定性流，`u∈0..9999 < detection_bp`，概率由受检覆盖、可观测证据和具体器材给出。侦测随机只控制是否获得证据，不可再次抽签决定账上的货是否“真的存在”。

## A13. 一条可检验的跨系统反应链

同一个世界先跑基准 B，再在相同分钟/相同随机种子派生干预 I。只改变一条已知铁路容量为原来一半。比较：

1. 该 link 上同窗口总 admission 不超过新额度；不使用该 link 的无关运单状态相同。
2. 一批实际粮食迟到；居民已付但未收到的数量仍在途，不能计消费。
3. 若居民原库存不足，consumed 降低、food_gap 增大；如果有足够库存，则不要求马上增压。
4. 企业若依赖缺失原料，下轮实际批次降低；其工资是否下降取决于合同，不自动同步扣薪。
5. 食品实际短缺进入次日已融资需求与价格；提高价格不能替代未到的粮食。
6. 群体直接生活经验和已到报告改变 stress/偏好，政治组织复查其策略。
7. 政府可能按规则动用预算/合法优先权；成功执行后改变未来运输分配，民用货主损失与补偿均有记录。
8. 军队如果有足够弹药库存，短期战力不变；库存耗尽后实际射击减少，再改变交战结果。

测试必须验证这些条件因果，不要求每次断桥都必定导致同样政变。另一干预只换运输方案，第三个干预增加现金但不修桥：前者可能改变到达，后者不能越过物理断路。由此检验玩家选择能改变结果，而不是写一条预设事件剧情。
