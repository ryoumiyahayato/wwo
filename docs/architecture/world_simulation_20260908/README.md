# WWO 连续世界模拟实施规格

> 2026-09-08用户反馈后的状态：本包保留为历史提案，**不再作为工作AI的整体实施指令**；尤其不默认执行W00→W21或替换正式Runtime。当前重点改为[不同场景下的组织、权力与决策设计](../ORGANIZATION_SCENARIOS_20260908.md)。原包中的具体经济、金融和战斗模型仅供后续按需参考。

调查基线：`85c073649e1ed17594f2a41d4f2081feceeabe8b`，2026-09-08，本地检出与远端 master 相同。

本交付是**供工作 AI 实现的设计规格**，没有修改游戏代码、替换产品入口或宣称新玩法已经完成。算法和参数是本次提出的模型选择；现有实现、待实现内容、验收目标分别标识。

建议采用的完整运行方式是：**在唯一世界时间上，以整数资源账结算持续过程；在明确边界统一收集竞争需求、分配资源、提交变化，再让人物和机构根据其知道的结果重新决策。** 经济循环、人事变化、政治程序和战争都接入这条顺序。离散事件用于定位下一次边界；日常生产、消费、利息和补给仍然必须结算。

这套方案的实现入口选用已有 `VNextWorldRuntime`。切入正式产品时替换 `FormalWorldSimulation` 的运行职责；不把两个时钟嵌套运行。地图表现可继续复用，经济数据和世界身份必须显式迁移。

按以下顺序阅读：

1. [仓库调查与取舍](audit.md)：实际运行链、现有代码可复用部分、不能直接拼接的地方、验证证据。
2. [运行与状态规格](runtime.md)：唯一事实、类型和单位、时序、原子提交、调度、存档、数据接入。
3. [连续算法规格](algorithms.md)：从人力、收入、消费、价格、生产、运输，到信贷、政府、政治、战争及其他组织的确定规则。
4. [工作 AI 执行单](execution.md)：依赖顺序、精确改动位置、每项任务的输入输出与失败条件。
5. [验收数据](acceptance.json)：有固定输入和预期结果的机器可读样例，以及集成、性能和行为门槛。它是测试规格，不是现成测试运行器。

工作 AI 先执行 `W00`，然后按依赖执行。每个任务同时交付实现、配置、针对性的失败测试和正式组合测试。只有注册类、增加字段、生成报告、通过旧夹具，都不能将该任务标为完成。中间可以使用小型数值夹具验证算法；完整交付必须运行同一个 Current World，不能把旧 Alpha 或一个局部演示场景切成普通启动世界。

首个需要消除的技术阻塞是**经济与军事的共同提交边界**：双方先提交同一个运力窗口的全部需求，Spatial 只分配一次，再让双方采用最终结果。仅按顺序调用已有两个 `advance` 方法无法满足这个条件。
