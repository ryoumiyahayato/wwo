# WWO：不同场景下的组织、权力与决策设计

> 后续范围：用户已进一步要求完整的社会结构与权力拓扑。当前主要交付见 [社会结构与权力拓扑规格](../design/SOCIAL_STRUCTURE_AND_POWER_TOPOLOGY_20260908.md)；本篇保留为较早的五类组织专项样例，不替代新规格。

状态：根据用户2026-09-08反馈重新收敛的**设计方案**。基线仍为 `85c073649e1ed17594f2a41d4f2081feceeabe8b`。本方案重点是组织如何组成、由谁代表、如何作决定和把决定交给现有领域执行。上一版 W00→W21 不再作为建议实施顺序；本次不提出替换正式 Runtime、重建账本、改价格或战斗公式的要求。

配套：[五种组织的结构样例与预期行为](organization_scenario_examples_20260908.json)。其中 `core_v1` 是可交给现有 OrganizationCore 验证的组织结构；`governance_design` 是拟增加的治理规则，不能当成已经实现。

这份设计中的组织名称、金额、议会席位和章程均为**机制样例**，不冒充某个1900年国家或企业的准确制度史。

## 1. 先把组织图的含义定清楚

WWO 中，一个组织表示：**一个有持续身份、内部角色和办事规则，能由特定人物代表的集体。** 组织的不同，主要体现为组织构成、职位产生方式、授权范围、决策程序及对外关系不同。

不能仅画一棵大树。至少要区别下面三种关系：

| 关系 | 表示什么 | 不自动表示什么 |
|---|---|---|
| 结构隶属 | 工厂管理处属于公司；地方支部属于政党 | 上层每个任职者拥有下层全部权限 |
| 有类型的治理关系 | 谁任命、谁批准、谁监督、谁临时指挥 | 两个组织合并、资产归属转移 |
| 外部业务关系 | 雇佣、持股、贷款、采购、谈判、结盟 | 对方成为自己下属 |

例如：公司与其采购处可以有 parent 关系；公司与独立工会不能有这种 parent 关系。国家议会与行政政府是两个互相制约的机构；不能把议会挂在政府下就推断部长可以命令议员。股东拥有股份，也不自动成为工厂的指挥者。

组织只保留结构和引用。资产所有权、合同、雇佣、债务等事实继续查相应领域；这里不复制它们。`external_relations` 中只保存本领域拥有的联盟、认可、监督、任命或委托关系，业务事实只保存 reference，不再写第二份债权/股份/劳动表。

## 2. 用现有结构表示，避免为了图好看新增实体

| 现实中的东西 | 在方案中怎样表示 |
|---|---|
| 有身份的集体 | Organization，使用现有稳定 ID |
| 有自身人员、负责人和持续职责的部门/分支 | 仍是 Organization；用现有 parent 表达结构隶属，角色标为 internal_unit |
| 董事长、总经理、部长、议员、军长 | Position；不是另建同名 Organization |
| 某人当前在任 | Appointment；指向 Person 和 Position |
| 董事会、议会、代表大会 | 有真实成员/席位和集体决策职责时，表示为组织或内部单位；投票者从其席位/会员中读取 |
| 临时开一次会 | ProcedureInstance，挂在召集组织上；不成立一个新组织 |
| 工厂、营房、印刷机、土地 | 已有领域的设施/资产引用；只有工厂管理班子需要单独部门时才创建管理组织 |
| 一个师的指挥机关 | Organization；实际兵员、装备、位置与作战状态是 Military Formation |
| 两党合作组阁 | Agreement；不自动创建能控制两党的“联盟上级” |
| 100万人支持某党 | Politics/Population 提供支持与选民输入；不自动成为100万名党员 |

部门采用现有 Organization 的成本很低：没有独立决策、预算、人员或职责的层级不创建。小店通常只需一个组织和一个经营职位；不能强迫它配置董事会、财政部和人事处。

普通雇员、工会会员、股东、党派支持者、政府官员是不同关系。一人可以同时是公司雇员、工会会员、党员；所有权和任职也可交叉。选择一次行为时必须说明**本次以哪个身份代表谁**，不能把这些身份合并成永久权限。

### 组织发生变化时，具体改哪一部分

| 情形 | 组织侧的变化 | 需要另行处理的事实 |
|---|---|---|
| 创办小店、成立支部 | 创建身份，按成立依据建立首批职位/成员/任命；记录创设者的依据，不能先要求尚不存在的董事会投票 | 出资、场所、登记或雇佣走对应领域 |
| 经理离职、内阁改组、军官阵亡 | 结束相关任命，撤销依赖它的个人委托；按代理/补选/任命规则补位 | 组织原有合同、债务、设施和既往决定仍在 |
| 公司收购另一公司 | 更新正式持股关系；按目标公司章程换任董事或经理 | 不自动重挂全部部门、吞并现金或移交每项许可证 |
| 政党分裂、工会分立 | 新组织有新身份；成员明确转入或保留兼属；另定谁有权转移资源 | 原组织资产和合同不按会员人数自动平分 |
| 部门重组、部队改编 | 经有权程序调整结构；逐项重验依赖旧部门/范围的授权，记录生效边界 | 人事、预算、设施和编制的转移分别交所属领域 |
| 组织解散 | 停止接受普通新业务，结束普通任命；必要时按明确依据保留限定清算角色 | 未履行合同和债务继续处理；不能直接删除组织ID以抹去历史 |

是否获得国家承认是另一项制度事实。未经国家登记的社团仍可能存在内部成员和首领；内部授权不能冒充法定许可。上述成立/解散流程先按实际场景增加有限规则，不为此建立一个通用法律解释器。

## 3. 在现有 OrganizationCore 上补什么

已读代码：`scripts/vnext/organization/organization_core.gd`。它已有组织身份、单 parent、成员、职位、任命、capability 与严格快照恢复。`has_capability()` 只查询人物在该组织的任命和字符串权限；没有目标范围、金额、程序、委托和到期语义。现有实现没有接入普通产品运行链。

建议保留它，并在组织边界内补下列记录。不是六个新的世界系统，也不是每种组织各写一个模拟器。

| 记录 | 最少字段 | 解决的问题 |
|---|---|---|
| 职位任用规则 | position_ref、选任程序、任期、代理规则、兼任限制 | 谁能任命谁，空缺后怎么补位 |
| 有范围的授权 Grant | holder_position、represented_org、operation、target_scope、conditions、basis、validity | 某职位具体能对什么作什么决定 |
| 决策程序定义 | 发起资格、参与资格、法定人数、通过条件、确认/否决步骤、执行职位 | 董事会、任命、投票和谈判怎样形成有效决定 |
| 决策实例和决定 | proposal、规则版本、参与资格记录、阶段、投票/签署、结果、授权对象、有效期、执行引用 | 决定能保存、追踪，结果有明确内容 |
| 治理关系 | source、target、relation_type、scope、basis、validity | 任命、监督、临时指挥、结盟等跨树关系 |
| 部门资源绑定 | org_id、account/site/formation/contract引用及用途 | 知道该找哪个领域，不能凭引用获得操作权 |

这批记录可以集中放在一个 `organization_governance.gd` 的有类型数据集合中。授权检查和程序推进使用独立小函数/服务，OrganizationCore 继续负责其现有结构。不要建立可运行任意表达式的章程语言；第一版只支持下文列出的有限程序和条件。

任命起止、生效依据和结束原因应保留在任命 owner 中。需要升级现有 schema 时明确写 `v2` 并迁移，不能往严格 v1 快照里偷偷塞字段。旧 `has_capability` 保留为粗查询；真正组织行为必须经过“选定任命＋具体目标”的检查。

现有“同组织一人只能一项任命”对兼任秘书、委员等场景过紧。建议将其改为默认沿用旧限制、由职位规则明确允许兼任；禁止重复占同一席位及声明互斥的职位。董事长本身可包含董事表决职责，不需为每一项职责增加职位。不能靠伪造部门规避兼任限制。

## 4. 谁能代表组织作决定

一次组织行为带上以下身份，不由 UI 自行勾选权限：

```text
ActingContext
  person_id
  acting_organization_id
  appointment_id
  represented_organization_id
  decision_id? / delegation_id?

ActionRequest
  operation
  target_refs
  amount_or_quantity? + unit?
  business_commitment_ref?
  requested_effective_time
```

例如采购处负责人可以“在采购处职位上，代表公司，采购工厂A的维修材料”。采购处、代表的公司、签署的人、目标工厂必须能够区分。

授权检查按固定顺序：

1. 查正式人物状态：是谁、能否行动；查指定任命是否在生效期内。
2. 查任职组织和代表组织是否有效；确认这项任命允许代表该组织。
3. 匹配 operation；检查目标部门/设施/部队/辖区是否落在 grant 范围。
4. 查 charter/law/decision 等依据是否有效；必要的同意、批准和确认是否齐全。
5. 有委托时核验委托链只收窄权限、仍有效、没有循环；默认不允许再转委托。
6. 将授权证据和请求交给业务领域。领域再核验其掌握的账户、预算、物资、实际控制和执行条件。

结果必须区别 `无权提出`、`有权提出但待批准`、`已经批准但无人签署`、`签署有效但缺资源`、`已经执行`。一个灰色“权限不足”不能表达这些不同情况。

### 四种权力要分开

| 权力 | 含义 | 示例 |
|---|---|---|
| 提出 | 把事项送进有权机构的议程 | 厂长提出扩建方案 |
| 批准 | 满足组织规定的共同决策条件 | 董事会批准扩建上限 |
| 签署/代表 | 让指定组织承担该项承诺 | 总经理签施工合同 |
| 执行 | 在领域里进行具体操作 | 财务付款、承运方发运 |

董事会批准扩建，不意味着任何董事都能从公司账户提款。财政部长有支付签署权，不意味着可以绕过议会批准预算。上级能够任免下级，不自动拥有下级全部专业操作权。

### 委托和限额

职位常设授权来自章程/制度；人物临时授权来自某项有效委托。前者可在换任后由新任人依法使用；后者若以某个任命为依据，则该任命结束后停止接受新行为。

金额限额必须带单位、目标、业务承诺范围及累计范围。比如“项目P累计最多100”，执行60后只剩40；不能拆成两个60绕过。已执行/已承诺金额从 Finance/合同记录查询，组织不再记另一份现金账。

已经合法签署的组织合同继续存在；签署人离任不自动使合同消失。尚未签署的草案重新交有效任职者处理。决定若授权的是职位，新任者可以执行；若指定的是某个人，换人需要修改决定。

## 5. 组织决策使用有限的程序模板

共同流程为：**提出事项 → 确认参与资格 → 收集意见/投票/签署 → 达到条件形成决定 → 交指定职位执行 → 记录领域结果**。投票、任命、谈判的条件不同，不能只套一个“投票成功率”。

| 模板 | 参与者来源 | 决定怎样成立 | 常见场景 |
|---|---|---|---|
| 单一任命者 | 制度指定的当前任职者 | 有效签署，候选资格和职位容量成立 | 老板任经理、部长任处长 |
| 集体表决 | 指定席位的在任者或合格会员 | 法定人数＋明确多数门槛 | 董事会、工会大会、议会 |
| 加权表决 | 股权/代表名额等正式登记引用 | 有效票权重满足门槛 | 股东会、代表大会 |
| 提名后确认 | 有提名权者＋指定确认机构 | 两步骤都完成，任命才生效 | 部长提名及议会确认 |
| 按顺位继任 | 经制度确认的候选顺位 | 空缺事实成立、候选合格、必要确认完成 | 世袭、依法代理、战地接替 |
| 双方协商批准 | 各方有范围的谈判代表 | 同一文本被各方按自身程序批准并签署 | 劳资协议、联合政府协议 |

授权任命不能是“有 appoint 字符串就任命任何职位”。规则必须指向可任命的 position 集合。世袭顺位也必须来自具体血缘/继承规则输入，不默认“随便找一个亲属”。

### 表决时必须写死的规则

- 资格来源、资格截止点、法定人数的分母、空缺席位是否计入；
- 通过按全部席位、出席人数还是有效赞成/反对票计算；
- 弃权、平票、回避、候选本人投票如何处理；
- 何时截止、谁能延长、谁有否决/复议/解散程序；
- 成功结果具体授权什么、给哪个职位执行、多久有效。

通用起点：投票开始时冻结资格规则和名册；之后死亡/失去资格者是否保留已投票、是否改分母，由该程序的明示规则处理。默认保留合法投出的票，禁止失去资格后新投票；分母按开会时固定席位数。不得在投票失败后临时减少分母。涉及依法必须重开的选举使用显式重开状态。

董事会示例：5个投票席位，至少3人出席；通过条件为赞成票严格超过出席人数一半，弃权计出席。3人到会、2赞成1反对，通过；4人到会、2赞成2反对，不通过。这是该样例的规则，不是所有议会/企业的通用法律。

只有涉及该会议、任命或协议的组织记录参与更新；一次党内投票不需要和全世界工厂一起提交。需要同时换任的旧任结束/新任开始在组织边界内一次完成即可。

实现时将“程序结果”与“领域执行结果”分开保存。程序可以处于草案、收集意见、待确认，最后成为通过、否决、撤回或到期；通过后对应的执行事项另记待签署、已提交、受阻或完成。撤回提案的资格也由程序规定。每票绑定参与者/席位及事项ID；样例默认每个票权只提交一次，重试相同提交不新增票，改投须使用明示规则。确认绑定提案版本；改变金额、候选人或协议文本后，不能继续使用旧版本的批准。

## 6. 公司：资产所有权、董事会与经营权分开

```text
河谷机械公司
├─ 董事会                 ← 内部决策单位，5个投票席位
├─ 总经理职位             ← 公司职位，不是一个新组织
├─ 采购处                 ← 负责人代表公司在限定范围采购
└─ 工厂A管理处            ← 厂长，引用生产设施 site_A

股东 ──股份登记引用── 公司
公司 ──雇佣合同引用── 工人
工会 ──谈判关系── 公司    ← 工会不属于这棵公司树
```

| 角色 | 怎么产生 | 能做什么 | 不能直接做什么 |
|---|---|---|---|
| 股东 | 正式股份登记 | 按股权规则参与选董事、改章程等事项 | 因持股直接调工人/部队 |
| 董事会 | 股东会选任或章程规定 | 任免总经理、批准大额投资、确定代表权限 | 每个董事单独花掉投资额 |
| 总经理 | 董事会任命 | 代表公司签常规合同；提出并执行已批投资 | 修改董事会资格或无限融资 |
| 采购负责人 | 总经理在任命授权内任命 | 在项目、品类、额度内询价/签采购承诺 | 采购另一家子公司的资产或绕过限额 |
| 厂长 | 有权任命者任命 | 对绑定设施排产、报告缺料、申请维修 | 把部门账户视为自己的私人现金 |

**完整情形：厂长要扩建，预计金额300。**

1. 厂长提交 site_A、用途、需求、金额、期限；该职位只有提议权。
2. 总经理可调整并送董事会；常规签署上限100，因此不能直接签300。
3. 董事会按5人模板表决，形成仅针对扩建项目P、总额300的决定，指定公司总经理签署。
4. 总经理代表公司签P的合同；Finance/Contract检查真实资金与承诺条件。
5. 批准成立但现金不足时，P仍是获批项目，执行状态为缺资金；董事会决议不失踪也不产生300现金。
6. 后续合同若已用200，新的150超出P剩余额度，必须修改项目决定；拆单不能逃过累计检查。

**组织差异如何配置：**

| 企业形式 | 结构差异 | 决策差异 |
|---|---|---|
| 个体经营/小店 | 一组织＋经营者职位，必要时仅Person直接经营自有资产 | 所有者依法担任经营者，不强制董事会 |
| 合伙企业 | 合伙人资格引用＋经理职位 | 借款/新增合伙人可要求全体或特别多数 |
| 股份公司 | 股东登记＋董事会＋经理 | 股权决定董事选任，董事会决定管理授权 |
| 国有企业 | 公司仍保留身份、设施、账户；出资/任命关系来自公共机构 | 指定机构可任董事或下达有制度依据的经营指令，不自动合并国库与公司现金 |
| 合作社 | 会员大会＋受委托经理 | 可配置一人一票；票权不取股权金额 |
| 企业集团 | 母子公司是独立组织；持股关系从资产领域读取 | 控股影响董事选任，子公司经理依子公司任命行事；不能沿 parent 自动获得资产操作权 |

## 7. 政府：同一政治实体中的多套职权关系

国家/政体身份继续使用已有政治实体。它把国家机构关联起来，但不是能向所有机构下命令的超级组织。

```text
同一 polity 的机构集合
  议会（组织） ──预算批准/监督── 行政政府（常设组织）
       │                         ├─ 财政部
       └─特定任命确认             ├─ 内政部
                                 └─ 战争部
  司法机关（组织） ──司法审查── 指定事项
  地方政府（组织） ──法定权限/合作── 中央机构
```

行政政府的组织身份保持稳定。“换一届政府”改变领导任命、联盟和议程，不能新建一个空财政组织丢掉旧合同。议会和法院不放入行政政府的 parent 树；地方政府是否结构隶属中央必须按制度，而不是按地图面积大小决定。

**财政支出样例：**议会批准预算，财政部长只能按预算范围签支付；具体付款由Finance执行。部长可以提出加预算，没有权修改议会投票结果。地方行政官的管辖scope是地区A；他在地区B提交同类行为要被拒绝或向B请求协作。

### 不同国家制度改变哪些组织配置

| 场景 | 职位来源 | 制约关系 | 同一骨架中的表达 |
|---|---|---|---|
| 议会制 | 议席来自选举；政府首脑依信任程序产生；部长依任命规则 | 政府要获得议会规定的支持，预算由有权议院处理 | 任用规则引用议会信任结果；独立预算程序 |
| 总统制 | 总统选任程序与议席程序分别存在 | 特定任命需确认，预算/否决按制度配置 | 提名后确认模板；总统和议会无 parent 继承权 |
| 君主直接任命政府 | 君主职位按继承/确认产生；官员按授予的任命权产生 | 宫廷、顾问会或地方权利按具体规则存在 | 顺位继任＋单一任命；不额外创造“君主经济算法” |
| 联邦/地方自治 | 中央、地方职位分别依各自制度产生 | 中央只对列举事项有权限 | 地方不是中央全权下属；scope分权、共同批准事项另列 |
| 殖民/保护关系 | 本地与上级机构分别有身份与职位 | 条约/授权保留本地部分权限，上级只获得列明范围 | mandate/approval关系＋地域与事务scope；不把本地全部机构合并成宗主国部门 |
| 政党高度控制政府 | 党组织选干部、提出议程；国家任命按有效制度成立 | 党内命令可能约束党员行为，公共权力需国家职位或明确制度授予 | 党职与国职分开，同一人物可兼任；党员身份不自动允许动国库 |
| 军事接管/争议政府 | 军事力量可以改变实际占领/控制；任命依据可能受争议 | 法定地位、实际控制和外部认可可能不一致 | 保存所据的制度/接管记录及争议状态；实际强制走已有Military/执法过程，不凭组织字段自动改地图 |

一个政府的结构差异要落在这些字段和程序上，不能只保存 `regime_type=monarchy` 然后仍然套总统—议会模板。立法、法律适用范围和人民支持继续由相关领域提供；本设计不重写政治支持率公式。

## 8. 政党：争职位、组织候选人与协调议程

```text
政党A
├─ 全国领导机构           ← 党主席等职位
├─ 地方支部               ← 会员与地方负责人
└─ 议会党团               ← 党内协调单位

党团成员 ──另有任命── 议会席位
政党A ──组阁协议── 政党B
政党A ──支持/反对── 提案与候选人
```

党主席、党内成员、党团成员、议员和政府部长分别记录。开除党籍不会自动删掉议会席位，除非该选区/国家的席位规则明确如此；政党领导也不能在没有授权的情况下代所有议员投票。

| 事项 | 谁发起 | 谁决定 | 结果 |
|---|---|---|---|
| 接纳/开除成员 | 地方负责人或有权组织 | 章程中的审查/申诉程序 | 成员身份改变 |
| 选党主席 | 章程允许的提名人 | 会员大会或代表大会 | 党内职位任命 |
| 提名公职候选人 | 地方支部/领导机构 | 初选、代表会议或章程授予的提名者 | 成为候选人，尚未获得公职 |
| 联盟谈判 | 党内有权谈判职位 | 各方自己的批准程序 | 对同一文本的合作承诺 |
| 支持预算/政策 | 党团领导协调 | 各有权投票者按制度投票 | 议会的实际决定，不由党内support代写 |

**完整情形：A有40席，B有20席，C有40席；组阁需至少51票。**

1. A、B谈判：支持首脑候选人X；财政部长候选人Y；承诺两项议程。协议是合作条件，不能直接把Y写进财政部长职位。
2. 两党按各自章程批准同一协议版本，党内谈判者不能单方面承诺超过授权的职位/政策范围。
3. 议会进行信任程序。A40票、B仅8票支持，则48票，不通过；名义联盟拥有60席不能替代实际投票。
4. 若实际60票通过，依制度完成首脑任命；X再按任命/确认程序让Y就任财政部长。
5. Y从任命生效边界取得财政范围授权。Y仍可能因预算不足无法付款。
6. B退出联盟，改变协议状态与未来合作输入；已付支出不回滚，政府是否辞职/重组取决于信任或任期规则，不由退出事件直接删除政府。

### 政党组织差异

地方自治较强的政党，把地方候选人决定权留在支部；集中制政党可把部分任命/提名权交全国机构，但必须明确列出。干部型政党与群众型政党区别在会员资格、代表方式和组织参与规则。一次性选举联盟只需协议；长期有人员与资金的联盟秘书处才创建组织。

Politics负责支持者倾向、政治竞争和议程输入；组织程序负责把合法结果变成党职、公职授权或正式提案。两者之间传递具体候选人、职位、提案和票权引用。

## 9. 军队：行政隶属与作战指挥分开

```text
战争部
└─ 陆军机关
   ├─ 第一军机关
   │  └─ 第十师指挥机关 ──引用── formation_10
   └─ 第二军机关

第十师 ──限期作战配属── 第二军
原行政归属仍可保留第一军
```

`parent` 表示常设编制/行政结构；作战指挥用有scope和有效期的 command_assignment。薪资、补充、任免、日常行政与作战命令是不同operation，不能因为一个上级军衔高就把全部权限合并。

| 角色 | 授权范围 |
|---|---|
| 战争部长 | 预算、组织与高级任命等制度授予事项；不默认每条前线战术命令 |
| 陆军/军级指挥官 | 指定任务和编制内的作战指挥；依据当前作战配属关系 |
| 师长 | 对指定formation的作战命令与下级任命范围 |
| 军需负责人 | 指定组织/部队的补给申请、已批采购或分发指令；不自动能下攻击命令 |
| 基层军官 | 所辖子单位任务；不因玩家身份获得整个战区指挥权 |

**完整情形：第十师临时配属第二军三天。**

1. 有配属权的陆军职位批准，决定明确formation_10、作战指挥事项、起止边界和接收指挥职位。
2. 有效期内，第一军不能再向该师新发本范围作战命令；其行政补给职责可继续。
3. 第二军可以下达本范围命令；Military仍检查部队状态、位置和行动条件。指挥权转移不会移动部队。
4. 新命令按通信/传达过程到达后，由Military的命令替换规则处理；不能在组织关系改变时倒写过去作战结果。
5. 三天届满按决定明确的恢复安排处理。已有行动是继续、等待确认或由新指挥者接管，由命令类型规则决定，不能直接抹掉。

每个formation在同一时段、同一指挥事项下只有一个最终指挥链。第二份重叠配属必须拒绝或明确替换第一份；`supported_by`、协调和联络不构成第二个最终指挥者。临时代理指挥使用代理任命，指定范围/有效期/结束条件；一个人物空缺不能冻结整个军队，但也不能任意让玩家升级。

民兵、地方武装、正规军共用这些记录，区别在任命来源、服从关系、编制稳定性和合法性。实际兵力、弹药和战斗规则仍归Military及资源owner；不新增一套“武装组织战斗算法”。

## 10. 工会：会员授权与实际劳动参与分开

```text
行业工会
└─ 工厂A基层分会
   ├─ 分会负责人职位
   └─ 合格会员/会员代表

基层分会 ──集体谈判── 公司
会员 ──正式雇佣引用── 公司岗位
```

工会不是公司的内部部门。会费、基金余额归Finance；会员资格归组织；某人受雇在哪、能提供多少劳动归Labor。非会员工人仍可工作；会员也可以已失业或受雇于其他单位，因此罢工scope必须指向具体雇佣范围。

**完整情形：公司100名雇员，其中60人属于该分会。**

1. 分会负责人依章程提出谈判/罢工事项，列出雇佣范围、工资诉求、最早班次、最长时限和基金承担范围。
2. 罢工表决规定60名合格会员中至少31人参加、赞成超过参加者一半。50人投票、35赞成15反对，表决通过。
3. 结果授予负责人在该范围和期限内组织行动的权利，不能命令全公司100人自动停工。
4. 若实际35名在职参与者确认参加，Labor从下一班次扣除这35人的可用劳动；其余65人不因表决自动停止。领域处理工资/劳动合同规则。
5. 基金资助指向具体参与者和额度。基金不足时产生待决策问题，不能创建一笔虚拟无限罢工补贴。
6. 公司代表与工会代表签署同一版和解文本。若文本超出原谈判授权，如工会授权最低涨薪6%却只谈到5%，必须回会员程序重新批准。
7. 双方签署并达到生效条件后，Labor/合同领域按覆盖范围改变工资条款和行动状态。工会内部通过一份协议，不能单方面改公司工资表。

工会联合会与地方分会可以采用代表制；职业工会按职业资格入会、产业工会按行业组织，企业工会按企业范围组织。是否允许一个人加入多个工会、协议是否覆盖非会员、分会是否能单独罢工，是制度/章程配置，不能都用一个union.kind推断。

大规模会员可以引用经过校验的群体会员登记/代表名额；票数不能仅取一个可随意填写的member_count。初次结构验收可用少量具名会员，正式扩大时由现有Population/Labor提供受约束的参与者输入，不在组织层建立另一套人口模拟。

## 11. 用其他组织检验这套结构能否扩展

| 场景 | 结构和角色 | 具体治理差异 | 交给哪个领域 |
|---|---|---|---|
| 银行 | 董事会、经理、授信委员会、分行 | 分行小额审批、超额上报、关联交易回避；股东不能直接提取客户存款 | Finance的贷款/支付命令；这里不设计准备金模型 |
| 媒体 | 出版组织、主编、编辑部、记者职位 | 出资人可有预算/任免权；主编有出版权；广告销售没有改报道权限 | Information的采访/发布过程，Finance付款 |
| 大学 | 校方、院系、学术委员会、教职 | 经费、行政任命、课程/学位审批可分别归不同机构 | 教育/研究领域的过程；不因一项校长命令即时增加全国技术 |
| 教会/慈善 | 总会、地方团体、负责人、服务单位 | 地方资产与人事是否自治由具体规章决定；宗教上级不自动拥有全部地方产权 | 资产、救济、教育、医疗过程 |
| 犯罪团伙 | 首领、分组、内部成员、临时合作 | 内部委托与国家法律授权分开；可以有事实上的服从，未必有法定地位 | 特定非法行为/强制过程；内部批准不赋予合法征税权 |
| 地主/家族 | Person直接持有资产，或确有共同管理时成立组织 | 财产继承、管理委托、租佃协商；不是所有家庭都必须模拟成公司 | Property/合同/Finance；社会关系只提供影响与接触 |

如果给报社增加主编签发规则就需要改世界时钟或中央资源相位，说明实现边界已经越出了本设计。

## 12. 组织作为政治舞台，具体有哪些可操作的事

政治交互围绕**待决定的事项和职位**组织：提名、竞选、任命、撤换、收集签署、谈判、争取票、结盟、提出议程、否决、复议、退出协议、修改章程、申请代理、挑战越权。

每个事项至少保存：目标职位/提案/协议、参与组织、各方代表的授权范围、需要哪些同意、当前已经取得哪些同意、谁还在反对/缺席、截止时间、通过后的执行者。支持率、好感、利益与威胁影响各人/群体是否同意；它们本身不能替代该同意记录。

NPC Controller只选择这些动作。可以按组织类型提供不同候选生成方式，但最终命令相同：公司经理关注已授权经营事项，党组织关注候选/协议，工会关注成员授权和雇佣诉求。

玩家仍控制一个人物。他在某职位上选择行为，替代这个人物在该职责上的NPC输入；**不是脱离人物任意切换一个职位的Controller**。没有任命就不能接管该职位；兼任多个职位时每条行为选一个身份。其他董事、部长、议员、会员和下属仍独立回应。

即使不设计新界面，也应让查询返回：我任什么职、依据什么在任、能代表谁、待办事项、需要向谁争取批准、我的决定将交给哪个执行者。实现者据此绑定现有界面，不另做一套所有组织通用的巨大控制台。

## 13. 只保留必要的运行接口

组织侧需要的时间信息只是：任命/授权何时生效失效、会议何时关闭、下一步骤何时到期。它从当前正式时间owner接收时间；不提出新的世界时钟。

建议有以下窄接口（拟议，当前代码尚不存在）：

```text
inspect_role(person_id, appointment_ref, now) -> RoleView
list_pending_matters(org_id, viewer_person_id) -> MatterView[]
authorize(context, action, now) -> AuthorityResult
open_procedure(context, procedure_ref, proposal, now) -> ProcedureResult
record_vote_or_signature(context, instance_id, choice, now) -> ProcedureResult
advance_procedure(instance_id, now) -> ProcedureResult
get_execution_request(decision_id, executor_context, now) -> TypedDomainRequest
```

`AuthorityResult`包括授权依据、目标范围、尚缺批准与拒绝原因。`TypedDomainRequest`转给现有领域后，结果另记为执行完成、排队或失败；不能因为程序通过就伪造业务完成。

公司采购与军队调动若争同一线路，使用Spatial自己的共同需求窗口。这是既有接入应遵守的规则；不为本次组织设计先开发UniversalAllocator。会议时间、长期生产能否惰性结算，分别由既有过程owner决定；仅在速率和约束确实不变、耗尽/到期边界已安排时才能跳过重复计算。反馈中的惰性结算方向可以保留，但不成为本次五类组织落地的前置重构。

## 14. 具体开发范围与验收

本次组织设计需要的改动集中在四处，而非重写整个游戏：

1. **组织记录补充。** 在现有core旁加入治理记录；补任期/依据/兼任规则，继续沿用稳定ID、组织局部职位ID和候选恢复。
2. **有范围的授权。** 用选定任命、操作和目标取代正式动作仅调用 `has_capability(person,org,string)`。复用领域的资源/权限检查，不新增组织余额。
3. **有限程序与五种配置。** 实现上述程序模板，交付公司、政府、政党、军队、工会的实际配置及下面的正反例。
4. **窄领域适配。** 将有效决定转成当前领域命令。先核对现有入口能接受什么；缺具体领域能力时标为“决定已成立，执行接入未完成”，不能为通过测试随手重做Economy/Military，也不能把stub成功计为正式玩法完成。

交给工作AI时，每项任务要求以下具体交付物。表中新增文件名是建议位置，不能把它们描述为仓库已有能力。

| 任务 | 应交付什么 | 本项完成判据 |
|---|---|---|
| 组织记录 | 在 `scripts/vnext/organization/` 增加治理记录定义；只有任命语义确需改变时才修改现有core并明确迁移 | 五份 `core_v1` 仍能恢复；新增记录拒绝悬空职位/依据；有效兼任与互斥任职有相反结果 |
| 授权检查 | `organization_authority.gd`：接收选定任命、动作和目标，返回范围、依据、缺少条件；补对应单元测试 | 同一人物换一个任职身份，权限按该身份变化；越范围、过期、拆单超额、委托扩大都被拒绝 |
| 组织程序 | `organization_procedure.gd`：有限模板的实例、票权、签署、决定及快照；五份样例转为测试输入 | 配套25个预期案例有对应断言；通过和失败均验证；中途保存恢复、重复提交和修改文本后重新批准可验证 |
| 领域接入 | 在当前正式组合入口接入组织服务，并为实际已有命令添加小适配；逐项标出尚缺的领域入口 | 已接通场景从人物行为到真实领域事实可追踪；缺入口的场景保持未完成，不以返回成功的假适配计数 |

这四项有数据依赖顺序，但不是四轮全项目重构。程序和授权验收应先集中使用配套场景；领域接入一次接通一个具体行为，并保留已经验证的其他行为。

普通产品接入必须挂在当前组合边界，不能因为OrganizationCore位于vnext目录就决定替换FormalWorldSimulation。现有 `docs/SOCIAL_ORGANIZATION_INSTITUTION_MODEL.md` 把国家机构称为单独Institution；本设计保留其公共职权/制度约束差异，但建议复用组织结构。这里是需要在实施时记录替代关系的设计修订，本次不静默改现行文档和代码。

### 五个场景各自要验证什么

| 场景 | 必须成功 | 必须拒绝或保持未完成 |
|---|---|---|
| 公司 | 有效董事会决定→当前经理代表公司签指定项目 | 单个董事提款；总经理超额自批；拆单突破累计额；持股直接下令子公司工厂 |
| 政府 | 正确辖区/预算/任命的部长请求进入领域 | 部长命令议会投票；地方官越辖区；议会过预算就自动增加国库 |
| 政党 | 党内批准联盟→真实信任票→法定任命→取得职权 | 联盟席位摘要自动当作赞成票；党主席直接当财政部长；退党自动丢所有公职 |
| 军队 | 限期配属后指定指挥者下达范围内命令 | 原指挥链继续越权新令；两个重叠最终指挥者；配属等同部队瞬移 |
| 工会 | 合格会员授权→实际参与名单→劳动领域接收 | 工会负责人命令全厂停工；单方改工资；超授权和解直接生效 |

共同反例：改变parent不扩大权限；换人不丢组织合同；已过期授权不能签新事；兼职不能混用身份；表决不够法定人数不能通过；同一签署重复提交只记一次；存档后继续同一会议/委托仍得到相同结果；改变字典顺序不能改变票数和权限。

这组验收的完成标准是：五种主体的差异都能由组织结构、职位、权限范围和程序表达，领域收到的是有真实发起人和依据的命令。现有数值模型可以继续演进，组织设计无需随价格或伤亡公式重做。
