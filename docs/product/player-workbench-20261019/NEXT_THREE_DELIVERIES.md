# 地图之外，接下来应当交付什么

日期：2026-10-19。性质：主体建设的实施建议与UI接入清单；不是已实现功能，也不占用R58编号。

## 1. 判断与证据范围

WWO的主体不应等同于地图。它要让玩家作为一个具体人物，在同一个持续存在的世界中认识处境、采取行动、等待结果并继续生活。军事、经济、组织三大算法本轮不施工；已经提供的只读数据和执行入口可以沿用，不复制其规则。

本次重新读取了GitHub正式分支`canonical/current-world`在`28cdc2dc37c68161dc7b3a3254692980cc75e972`的AGENTS、WorldState、FormalWorldPresenter、PersonView和架构说明。该提交日期为2026-10-14，说明对应R12。它不能代表用户本机R56/R57最新源码；本次也没有运行本机游戏。

实际读到的基础：WorldState已有唯一时钟、人物、玩家、空间、旅行和正式可变人口的组件引用。Presenter已经读取人物所在地、旅行视图和目的地。PersonView已经有个人财务、物品和记录，并非空模块。因此人物、旅行、人口、存档都不是从零重造的项目。

远端架构文档明确未记录独立正式Relationship和mutable Information状态；这只能作为远端缺口，不证明本机最新实现或独立工作线绝对没有。应先核对已有研究和最新源码，再确定接入。

当前AGENTS要求沿用WorldState、WorldBootstrap、Application、Presenter和现有Persistence，不恢复旧FormalWorldSimulation、组件注册表或启动互锁。项目旧说明中的产品目标可以保留，旧类名与旧进度不能覆盖现行代码。

## 2. 主体应当具备的完整过程

人物当前处境 → 已支持的行动入口 → 领域接受或拒绝请求 → 唯一世界时间推进 → 原服务产生进展与结果 → 玩家读懂反馈 → 保存退出 → 恢复同一人物和同一过程。

这不是另建“巴黎小世界”，也不是把浏览器原型变成游戏。接入必须发生在现有正式世界。地图负责观察与定位，不负责改变人物位置；UI负责读取和发请求，不在页面上结算、发薪或移动人物。

18项总清单继续见[FRAMEWORK_BACKLOG.md](FRAMEWORK_BACKLOG.md)。下面把它收敛为三份真正能够进入游戏的产物，不再给施工方同时塞入18套新系统。

## 3. 第一份产物：人物首页与明确的操作入口

**玩家得到的结果：** 从现有人物头像进入，一页知道“我是谁、在哪里、正在做什么、下一件需要处理的事是什么”。查看俄罗斯、法国或某个历史地点，不改变正在扮演的人物。

先在当前PersonView和MainShell里整理信息，不新建PlayerManager。

| 要显示的内容 | 已读到的原入口 | 本次接入原则 |
|---|---|---|
| 正在扮演的人物 | player_state.player_id、person_overlay.person | 永远读取当前控制对象，不取地图选中国家 |
| 实际所在地 | person.current_place_id、spatial_world.get_place | 与“正在查看”分栏；未知明确显示未知 |
| 当前行程 | person_travel.view(person_id) | 读取原阶段、原因和时间；不建立UI计时器 |
| 可前往地点 | person_travel.destinations(person_id) | 只显示原服务给出的候选；地图参考点不自动成为目的地 |
| 当前安排与结果 | 现有个人安排、旅行等只读记录 | 只展示已支持字段；不预造健康、技能或NPC关系值 |
| 地点详情和地图定位 | 现有WorldPage、Controller与请求入口 | “查看”“定位”“人物前往”分别命名、分别处理 |

界面以“今日处境”为首页，账务保留原页但不再占据整个人物入口。没有正在进行的行动，应显示清楚的空状态，而不是假进度条。某项行为需要三大系统的新规则才能成立，就暂不提供执行按钮。

范围只到：人物摘要、现有行程、原有资料导航、既有可用操作。来源详细说明收进可展开资料，不在普通正文反复堆“LOD、源域、准入”等内部词语。

**完成判断：** 用户不用翻开发文档就能看清人物所在地；浏览别国后人物首页不变；定位人物只移动相机；打开和关闭页面不触发世界重建、重复发薪或旅行请求。

## 4. 第二份产物：贯通一条已经支持的行动

**玩家得到的结果：** 提交一次真实请求以后，能看见它有没有被接受、为什么受阻、什么时候产生结果，以及之后在哪里查到这段经历。

优先选择当前正式旅行服务确实支持的一条路径；不要在文档里擅自指定不存在的巴黎—里昂车次。若最新版本没有任何可执行旅行，就改接另一条已经拥有正式执行与记录的行为，或明确指出缺少哪个必要入口。不用假按钮补洞。

行动显示统一采用容易理解的词语，但不强迫不同领域共享一套虚假的状态机：

- 尚未开始：显示目标和现有条件；确认后才发出请求。
- 进行中：显示原服务给出的阶段、开始时间及可取得的预计时间。
- 暂时受阻：说明实际原因；没有合法重试/取消接口就不显示该按钮。
- 已结束：分别显示成功、拒绝、中断或其他实际结果，并保留相关对象入口。

“标为已读”不是“接受任务”；“查看进度”不能再次执行请求；画面卡顿或关闭页面不能让已接受的世界行动重新开始。

消息与记录至少分为人物相关消息、操作结果、系统状态和资料说明。它们可以复用现有消息抽屉与有界记录，但系统知道一条消息，不等于人物已经收到或知道它。正式个人知识需要对应状态后再接入，不直接从全知世界快照生成假传闻。

个人经历首先汇集已有真实结果，不先新增好感度、健康值、职业经验或强制历史任务。玩家临时收藏和搜索历史属于UI偏好，不变成人物知识。

**完成判断：** 同一个请求不会因刷新重复执行；行动受阻有具体原因；页面关闭后原行动按原时钟继续；已有过程保存和恢复后不重复开始；结果可以回到相关人物或地点，而不是只有一条消失的Toast。

## 5. 第三份产物：五槽存档、恢复与初次进入体验

**玩家得到的结果：** 清楚识别不同版本的存档，知道读档失败后当前游戏是否保留，并在首次进入时了解实际已支持的操作。

用户已有R33五槽及版本识别的交付记录。不能根据远端旧单槽文档推翻它，也不能把本原型中的v15示例强行固定为本机最新格式。

[save-recovery.html](save-recovery.html)是本次新增的存档界面交互样例，与已有[人物手册原型](prototype.html)配套。它不访问文件，不执行持久化，不模拟世界。

| 信息 | 玩家看到什么 | 必须避免 |
|---|---|---|
| 创建版本 | 该存档最初由哪个版本创建；缺失时明确未知 | 每次保存覆盖创建版本 |
| 最后保存版本 | 最近写入该存档的构建 | 把它当作格式版本 |
| 格式版本 | 原读取器实际识别的格式 | 新旧构建号不同就拒绝读取 |
| 内容和引用 | 所需对象、数据或格式是否满足原恢复约束 | 只看格式相同就承诺一定能读 |
| 读取进展 | 解析、检查、候选恢复及正式替换各自结果 | 元数据读完就显示“读取成功” |
| 失败处理 | 原世界保留、原槽保留、具体原因 | 先清空当前世界再尝试恢复 |
| 备份/转换 | 原实现真的支持才提供明确操作 | 假备份按钮、自动改版本号或自动迁移 |

创建版本未知与文件损坏是两回事。较新构建也不一定使用不兼容格式。UI不复制兼容判断，只展示原FormalPersistence的结果。

初次进入只做可以关闭的短帮助：当前人物、查看与定位的区别、已支持的行动入口、时间暂停/推进、保存与继续。没有支持的新身份不要伪装成可选择的职业；不强制连续点击一套长教程才能玩。

**完成判断：** 从已支持存档恢复原人物和原过程；不兼容或损坏有具体原因；失败不替换当前世界；退出是否保存明确；第一次进入不把全球可浏览范围误说成全球全部身份都已可玩。

## 6. UI具体调整建议

保留油画主菜单、现有四角HUD、黄铜时钟、国旗和底部机械半球仪，不另做一种冲突的美术风格。

正文与长列表优先采用原生Control和容器的可滚动阅读区；原自绘地图HUD无需为了统一而整块重写。基础字号以原项目缩放规则为准，不再通过不断缩小字体容纳长说明。

输入要有明确边界：弹窗关闭后焦点回到原按钮；Esc关闭最上层；输入框中的文字和快捷键不驱动地图；正文滚轮不能继续传到地球缩放。Godot 4.6的Control文档特别说明mouse_force_pass_scroll_events默认开启，MOUSE_FILTER_STOP并不单独保证滚轮不继续向父级传播。接入时核对现有根容器和事件路径，不能只改一个属性就声称解决所有输入冲突。

地图提示改成实际状态而不是开发术语：细节准备中、此处只有较粗资料、读取失败、适用细节已就绪。只有现有渲染层确认了对应状态，UI才显示；这不是要求在UI重新判断地貌覆盖或掩盖LOD错误。

## 7. 后续还值得做，但不要同一轮全部开工

人物关系、约定与失约、个人知识和通信、技能与成长、休息与身体后果、人物生命周期、完整迁居和生活地点，都有独立产品价值。它们不等于军事、经济、组织三套大算法，但会与这些领域共享人物、时间和资源事实。

下一批先接一条真实关系或一条有来源的消息过程，不新建六个总管理器。天气与季节可以后置；先区分环境显示与真正改变行动条件的环境状态。地图材质随季节变色，不等于已实现气候或路况模拟。

仍需以后明确的产品决定：一段人生结束后如何继续；公开历史图鉴与人物可知信息的边界；哪些开局身份真正可玩；普通生活时间压缩保留哪些关键选择。这些决定不阻止先完成前三份产物。

## 8. 多工作线怎么推进

地图维修线继续处理方格、精度与海岸；人物/UI线做以上三份产物。两者可以并行，不要求全球地貌全部完成才能做人物首页。

共享文件如MainShell、Presenter和Application由当前实际负责人串行提交小范围修改。分支只用于短期评审，不建立永久平行主线。不将10月14日远端整棵旧源码覆盖到最新本机；只取本目录设计，在本机最新接口上实施。

交付记录保持简短：这次玩家多了什么真实操作、尚未接通什么、修改哪些文件。不要再用新增纹理数量、文档页数或导出成功作为主体玩法的完成标准。未运行的检查不写通过；本次没有启动Godot、生成EXE或碰真实存档。

## 9. 本次新增原型的有限检查

Browser插件未提供，使用现有/usr/bin/chromium与Playwright把同一HTML载入内存。实际检查五槽选择、成功和失败流程样例、格式不支持与损坏时禁用、创建版本未知仍允许进入检查、Esc关闭与焦点返回、1250×720/960×640/390×844三种视口及两档字号。未发现这些操作中的页面脚本错误、横向溢出或外部网络请求。检查只针对本次新增save-recovery.html；没有把此前人物手册README的测试记录当作本次重测。

这不是Godot兼容性、真实存档读取或R57地图验收。截图和临时检查脚本不加入游戏包。
