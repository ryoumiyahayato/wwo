# 人物手册：界面与正式接入说明

## 1. 不替换地图，补人物阅读与行动入口

原型是五个页面的阅读/交互设计，不是另一套WWO游戏。它不包含经济、组织、军事、旅行结算或世界时钟。

保留现有油画菜单、四角HUD、国旗、黄铜机械时钟及底部半球仪。正常地图仍以观察为主。从现有人物头像/人物详情入口展开人物手册，再回到原地图。不要复制地图渲染器到每个页面，也不要用浏览器替换Godot正式UI。

当前正式分支的源码比本机落后。以下路径和方法名来自已核对的R12远端，接入时在最新本机工作树重新核对签名，只迁移必要改动。不要把旧MainShell整文件覆盖过去。

## 2. 五页负责什么

| 页面 | 正常内容 | 不该放进去的内容 |
|---|---|---|
| 今日处境 | 人物姓名、当前位置、当前行动、到期事项及合法状态摘要 | 以现金和市场数据占满人物首页；没有实现的健康值 |
| 行程与安排 | 原行动的阶段、预计时间、受阻原因、已支持的后续操作 | 独立计时器、假路线、万能成功率、虚假的取消按钮 |
| 地点档案 | 查找、同名类型、来源、浏览历史、收藏、明确定位 | 点选城市就移动人物；历史坐标自动生成旅客线路 |
| 消息与记录 | 人物消息、系统提示、资料说明；时间和原始来源 | 全世界隐藏状态；把日志当人物已经知道的事实 |
| 显示与帮助 | 字号、对比度、焦点/按键说明、地图图例和状态说明 | 没有实现的画质开关；每次开页面重新生成地图 |

原型为讨论留有明确的“状态样例”切换按钮。这些按钮不进入正式游戏：正式状态必须从现有服务读取。

## 3. 复用现有代码，不新增并行总管理器

| 需要的内容 | 本次读到的实际入口 | 接入动作 |
|---|---|---|
| 当前人物 | `world.player_state.player_id()`、`world.person_overlay.person(person_id)` | 继续由Presenter准备当页需要的字段 |
| 正式所在地 | `world.spatial_world.get_place(current_place_id)` | 与正在查看的政治对象分栏，不能互相赋值 |
| 当前旅行 | `world.person_travel.view(person_id)` | 展示原阶段和原因，不在UI重新算到达 |
| 可选旅行目的地 | `world.person_travel.destinations(person_id)` | 只显示服务实际允许的对象；不能取所有历史地点 |
| 个人安排和持有 | 现有`personal_economy_state`读取和`PersonView.refresh` | 不重新建钱包/消费规则；与对应工作线约定字段 |
| 页面及资料返回 | `MainShell.current_page`、`_history`、`WorldPage` | 整理既有返回顺序，不新增第二份导航状态 |
| 消息抽屉 | `MainShell._messages`及现有抽屉/通知入口 | 给已有记录分类与归档，不新建另一套Toast总线 |
| UI发动作 | `MainShell.action_requested` → Application现有请求处理 | 继续用原行动入口，字段不完整时明确不可执行 |
| 存档 | 最新本机R33以后`FormalPersistence`及槽位元数据 | 沿用五槽与可读判断，不根据旧远端单槽文档倒退 |
| 显示偏好 | 现有`InterfaceSettings` | 实际参数存在才接入；恢复UI偏好不改变世界事实 |

对未来关系和个人信息，仅在拥有真正的状态及结果以后接入页面。不要提前创建空接口、虚构消息或一批灰色功能按钮来表示“已建设”。

## 4. 四项容易混淆的操作，必须拆清楚

- **查看资料**：只改变当前阅读对象。
- **地图定位**：向已有Controller请求相机定位，不更改人物位置。
- **人物前往**：通过正式旅行服务执行；需要真实地点和连接，不等于定位。
- **标为已读**：只更新对应用户/人物的阅读状态，不接受任务、不自动答复、不完成行动。

历史资料允许作为地图图鉴公开浏览，不应因此让人物取得远方实时私人信息。玩家可看的资料图鉴与人物可用于决策的知识必须分别表述。

## 5. 布局与视觉

沿用深墨色底、象牙正文、克制黄铜边框；不制作现代大圆角仪表盘。外观服务于信息层次，不把每条事实套成一张金属卡。

人物手册在宽窗口采用左侧导航、主阅读区、必要时的右侧详情。较窄窗口改成顺序阅读；详情与正文不争抢同一小块空间。原地图HUD不是本原型重画的目标。

正文目标约16个逻辑像素起步，标题与按钮用独立字号；应结合原有缩放规则验证。当前原型是16/18两档，不把它作为Godot唯一硬编码值。长说明进入可滚动正文，不靠全部缩字解决。

常驻摘要只回答人物、所在地、当前行动和待处理事项。来源/证据说明进入可展开资料，不在每个普通操作里重复堆砌“原生、权威、LOD、源域、准入”等内部词语。

类别要同时有文字/形状差异，不能只用颜色。缺失值显示“未记录/资料未提供”，不能显示0。暂停与速度不要改变正在扮演的对象；地图LOD不成为个人生活时钟。

## 6. 输入与性能

Godot正式接入优先使用现有Control及容器能力，给正文、列表和详情清楚的可用尺寸。现有自绘HUD无需全面重写；新增可滚动阅读区应避免继续扩充绝对坐标拼接。

弹窗关闭后焦点返回原按钮。Esc优先关闭最上层；输入框聚焦时字符快捷键不驱动地图。装饰背景不接收鼠标；面板处理自己的点击和滚轮后不继续传给地图。

官方参考：
- [Godot 4.6 UI概览](https://docs.godotengine.org/en/4.6/tutorials/ui/index.html)
- [Godot 4.6 Control](https://docs.godotengine.org/en/4.6/classes/class_control.html)

这些是实现依据，不意味着项目已经改用全部原生控件。实际容器、焦点和事件处理须对照当前Godot版本与现有MainShell。

只刷新当前页面所需字段。隐藏页面不每帧复制全世界数据；搜索使用已解析的有界记录和索引；列表分页/限量；图层切换不重建人物状态。已读与收藏的持久化以后归明确的UI偏好或人物信息字段，不另建独立“玩家世界”存档。

## 7. 地图反馈改为四种明确状态

1. 已就绪：适用的请求完成，且覆盖达到声明的细节等级。
2. 细节准备中：保留可用底图，相机继续响应。
3. 此处只有较粗资料：数据限制，不显示永久等待。
4. 读取失败：说明受影响范围，提供确实存在的恢复操作。

“当前区域细节已安装”不能仅因为一个工作线程结束就出现。诊断ID与详细错误保留在可查看的系统记录中，正常提示使用可理解的中文。

## 8. 接入顺序与成果范围

先接今日处境和已有旅行/安排的只读概况；再接既有消息分类、资料搜索和明确定位；随后整理字号、滚动和焦点；最后再按真实行动接口加入请求控件。

完成标准是用户能通过原人物入口打开、看懂当前处境、跟踪一个原有行动、查看原因并返回原地图。不是新增五个空页面。

本次只交付本文、建设清单和HTML交互原型，未改正式GDScript，未运行Godot游戏。后续正式接入需要读取本机最新源码并走原存档/行动规则；不把原型演示数据导入生产。
