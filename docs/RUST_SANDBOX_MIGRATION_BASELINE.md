# Rust 沙盒迁移基线

2026-11-15。正式接入以 Rust `InitialWorld`、`GameClock` 和原生存档为权威。两条研究线保留自己的测试入口。下列历史结果来自对应源码及既有报告。

## 经济

[Economic Lab 第 23 代归档](https://github.com/ryoumiyahayato/wwo-economy/releases/tag/economy-gen23-closeout-20261024) 与 [20 家企业的源码、接口和运行证据](https://github.com/ryoumiyahayato/wwo-economy/releases/tag/production-network-v1-20261025) 均在 GitHub。生产网络报告记录了 29 个主情景、3 个只读复核和 2 个采购价格对照。原 `EconomyR1Slice` 使用既有时钟、Ledger、StockLots、订单和运输。正常 21 日情景产生 403 次已接受订单，支付工资 847，另有 65 到期未付。接受订单和实际交割分别计量。运行中研发、农业和采矿再生产、完整净利润仍缺验证。

| 能力 | Rust 正式世界已有 | 合并范围 |
| --- | --- | --- |
| 企业、地点和资金 | `formal_work.rs` 开设开局企业账户；`formal_bootstrap.rs` 提供正式地点和人物 ID；`formal_ledger.rs` 保存余额及支付责任。 | 复用这些身份与账户。补企业经营授权、企业站点、生产工艺和货批。 |
| 生产和设备 | `formal_macro.rs` 结算统计产量和市场需求；`formal_work.rs` 记录个体工时。 | 移植原配方、批次周期、安装状态及适配设备池。批次数受实际工时、设备能力、未预留材料、周期和数量上限约束。无法满足的必要条件明确停产。 |
| 采购、订单与库存 | `InitialWorld::buy_statistical_stock` 处理现场统计市场购买；`formal_stock.rs` 保存个人购入和消耗货批。`formal_purchase.rs` 另有法国旧开局首单维护路径，使用旧序列化格式。 | 复用正式账本与交易身份，移植企业报价、采购许可、预留、订单锁价及按交付结算。记录来源和货权；不让同一库存同时由统计和企业路径支配。 |
| 运输 | `formal_macro.rs` 已有统计货运和原生恢复，`formal_bootstrap.rs` 可读取正式交通线路。 | 复用线路和时间，补企业实物的运力占用、在途保管、分段交割和运费支付。 |
| 工资 | `formal_wages.rs` 按已完成班次创建工资责任、按现金支付、保留未付并能读档。 | 沿用原工资责任。生产成本读取已发生工资及分配工时。 |
| 成本 | `formal_ledger.rs` 保存实际资金变动。 | 按原 `EconomyCostAllocation` 追溯采购、运费和已发生工资；保留未知成本和未分配工资。 |
| 经营决策 | Rust 已结算宏观供需，已有正式人物行动。 | 复用实验中企业可知供应商、目标库存、承诺优先和增量贡献规则。以权限控制的 `economy_read_v1` 读取企业状态。 |

首个经济接入范围是已验证的两站点采购、生产、交付和成本链。先接可预留的企业实物货批和交付责任，再接批次执行和原采购决策。使用原生时钟和存档，逐笔核对实物、资金、工资责任和重复请求。保留原试验的开发参数标记。

## 军事

[PR #126](https://github.com/ryoumiyahayato/wwo/pull/126) 与 [固定运行报告](https://github.com/ryoumiyahayato/wwo/blob/f643199b48d630b371bc16b8d887707d4ea24ed1/docs/maps/layered_military_region.md) 记录旧正式入口和测试。独立军事仓库 [`1be6367`](https://github.com/ryoumiyahayato/wwo-military/tree/1be6367) 中，`military-godot/triple/{space,shell,port,test_continuity}.gd` 存有单一米制空间、同实例重入、乘员和弹药状态、返回协议及冷恢复测试。`modules/region_observation` 存有有界加载、地形边缘连接和局部碰撞。M 开发 v9／运行 v8 档案保留作规则来源和集成参考。

| 范围 | 已实现 | Rust 接入及缺口 |
| --- | --- | --- |
| 50×50 km | 两档共享的 50 m 区域高程。可显示最多 100 张 5 km 粗页。 | 在现有宿主接统一米制场景和视距裁剪。区域显示本身不提供整区近景碰撞。 |
| 25×25 km | 同一空间的观察范围；选邻区不移动原单位。同一战斗实例保留。 | 复用单位 ID 和场景。镜头切换只更新显示请求。旧观察切换会暂停训练活动，持续推进的正式战斗仍需宿主接入。 |
| 5×5 km | Ridgevale 原 4 m 地形、原生车辆和步兵、有限弹药、乘员上下车和局部碰撞。旧原生战场实验也有按需的 1 m 插值和变形。 | 先接原高程和有界地面碰撞，再接原 GLB 和动画，以已有角色 ID 和事件驱动车辆、步兵及结果。4 m 源数据与 1 m 插值范围分开记录。 |
| 远距离和空海 | 旧陆地原生交战和伤弹链有实跑；远区观察、M 战略裁决和外部正式接口有源码。 | 宽区持续交战、跨区地形查询和可玩舰船／飞机缺整合验证。空、海单位可用相同单位身份和生命周期，分别接水面和飞行模型。不要把旧 50 km 观察画面当作全图激活实测。 |

旧有实窗基线为初始 20 车、150 独立步兵及 62 个车组座位。PR #126 的 RTX 活动阶段约 1.9–2.8 FPS，驾驶和 30 FPS 目标未达标。停战和自然减载后帧率另外记录。Rust 下一阶段按实测分离地形安装、渲染、碰撞、角色更新和模拟／墙时预算，先保留一条真实车辆和步兵路线，再以原负载复核。

首个 Rust 迁移片段是 `battlefield_terrain.rs`。它直接读取原训练区清单和两套高程，复用原三角剖分与米制坐标。现有 `wwo-formal-state military-terrain <region-root> <x-m> <z-m> ...` 可读出同一坐标的实际高程和使用的 4 m／50 m 源。训练区为虚构资料。该片段供后续场景及碰撞共用，目前通过维护入口运行，未接入可游玩 3D 战场。地图和人物档案写入范围未变。
