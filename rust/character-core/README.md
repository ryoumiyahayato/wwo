# WWO Rust 人物核心

本模块将人物设计实现为可独立调用的 Rust 库。无 Godot、Bevy、渲染器或平台依赖；可供迁移中的 Rust 宿主使用。`serde` 和 `serde_json` 用于有版本的状态序列化，依赖版本保存在 `Cargo.lock`。

开发基线：WWO `main` 的 `10f451fadf8b2aa2de33626311f07c6eb62e3d35`。检查主线与 `sync/wwo-runtime-20261112` 时尚未找到 Rust Cargo 工程，因此这里新增独立 crate，不推测本地迁移接口，也不把独立模块称为正式游戏集成。

## 实现的规则

- **后台与前台分离**：后台保留体质、各领域知识/实践/学习倾向；`PersonView` 只提供姓名、年龄、状态、特征、经历和宿主允许展示的社会事实。它没有智力、魅力、成功率或属性加成字段。`snapshot()` 是存档级内部数据，不能当作人物页面接口。
- **具体能力与发挥效率分离**：行动定义知识和实践的权重；身体状态、任务体力需求和经历影响发挥效率，不删除已有知识。不存在万能能力总分。结果给出难以胜任、可以应对、熟练三档及原因。
- **社会条件优先**：资金、资产使用权、劳动、市场、组织、许可、引荐、信息分别向宿主查询。任何必要条件缺失或未知时，不再计算能力表现；返回具体原因。家庭背景文本不会授予资金或概率加成，家庭提供的真实款项、资产和引荐由宿主原系统记录。
- **有限成长与混合经历**：教育/工作事件推动知识和实践，学习具有递减收益且封顶；经历可同时增加知识、减少实践或降低发挥效率。临时效果到期失效，经历仍保留。同一经历来源不能再次奖励。按领域保留最近培训描述，避免逐次增长培训日志。
- **健康与寿命**：当前健康、恢复上限、永久损伤和先天体质分别保存。伤病会消耗健康，营养、休息、医疗和体质影响恢复，永久损伤不能自然恢复。成年后的渐进衰老影响恢复上限；死亡风险独立于健康清零，另支持疾病、致命损伤和外部事故死亡。死亡后不能继续训练或行动。
- **低频与一致规则**：只登记宿主已物化的具名人物，不展开普通人口；跨模拟日结算，同日调用直接返回。没有每帧处理，也没有玩家特权分支。死亡随机流由世界种子、人物 ID、日期共同确定，批量推进、逐日推进和存档恢复不改变结果。
- **持久化与失败处理**：保存规则、种子、处理日期、人物、事件序号和死亡记录。恢复检查版本、世界 ID、宿主日期、身份引用、重复人物、范围及健康上限。事件与跨日结算失败不采用部分修改；事件序号必须连续，避免重复伤害/训练。

`LifeRules::default()` 的年龄段、恢复量、风险和衰老参数都是 **GENERATED_SIMULATION_ASSUMPTION**，不是经过验证的 1900 年人口寿命表。日期 v1 使用每年 365 日的模拟年龄单位；真实日历由宿主换算。默认从 45 模拟岁开始减少恢复上限，125 岁进入必死风险段作为防止无限寿命的开发上限，不应把这些数值解释为历史或医学结论。规则保存在存档里；更换规则需要明确迁移，不能静默改变旧世界。

## 使用

从仓库根目录运行：

```sh
cargo test --locked --manifest-path rust/character-core/Cargo.toml
cargo run --locked --manifest-path rust/character-core/Cargo.toml --example social_opportunity
```

示例使用两个虚构人物，相同能力、不同现有资金和引荐：工人家庭人物会收到“积蓄不足”和“尚无担保人引荐”；商人家庭人物通过该示例的两个条件，随后评估经验。示例另外演示旧伤、30 日推进和存档往返。示例的账户与关系属于明确测试数据，没有创建正式人口、企业或游戏资产；其两项要求不是开办真实工厂的完整条件表。

接入另一 Rust 项目时添加路径依赖，例如在仓库内的 `rust/runtime/Cargo.toml`：

```toml
[dependencies]
wwo-character-core = { path = "../character-core" }
```

没有在仓库根部加入 Cargo workspace，避免擅自替换迁移工作的组织方式。

## 宿主接入责任

| 接口 | 输入/输出 | 宿主负责的事实 |
| --- | --- | --- |
| `CharacterHost::person_exists` | 稳定 `person:` ID 是否存在 | 从原人口/具名身份注册表读取；登记不增加人口。保留死亡人物身份以支持历史存档。 |
| `register(PersonSeed, host)` | 已物化人物的出生日期、初始能力和依据 | 出生日期不得用未知值冒充；已有伤病通过正式事件导入。初始能力属于显式假设或已有资料。 |
| `CharacterHost::living_conditions(id, day)` | 前一日到该日的营养/医疗/安全/休息 | 从实际消费、医疗、工作和环境记录得出。无资料返回 `None`；不得拿当前条件追补全部过去。 |
| `advance_to(day, host)` | 日期与新发生的死亡通知 | 宿主时钟提供累计时间并分日；死亡同事务反馈到人口、身份、在岗状态与权限规则。 |
| `apply_event(id, seq, event)` | 伤病、教育、经历、事故 | 只能由已授权且实际发生的领域事件调用，先结算旧时间，再应用新变化。一次只支持一个疾病过程；并发疾病明确拒绝，留待后续扩展。 |
| `OpportunityHost::condition` | 条件是否满足、原因和来源 | 从原 Ledger、资产、劳动、组织、权限与信息域读取。账户余额必须扣除预留，外币不直接相加。 |
| `assess_action` | 条件与能力表现的只读评估 | 行动规范是宿主规则，不接受玩家自行删掉必要条件。检查整体要求能否同时满足，不能让同一份资源重复满足多个要求。 |
| `view(id, SocialFacts)` | 可展示人物信息 | 事实需先经过观察者权限过滤，未知保留 `None`；不把完整后台快照送给玩家。 |
| `snapshot` / `to_json` | 后台状态 | 放入迁移宿主现有世界存档，不创建另一套现金或世界时钟。 |
| `from_snapshot` / `from_json` | 恢复候选组件 | 宿主先恢复相同世界与人物引用；日期必须一致。恢复成功后随整个候选世界一起替换。 |

当前 Godot 对应权威是 `VNextNamedPersonOverlay` / `FormalWorldPopulationState`、`GameClock` / `SimulationStep`、`FormalLedgerState` / `FormalPersonalEconomyState`、`OrganizationState` / `AuthorizationCheck`、`FormalPersistence`。这些名称仅作迁移映射；本 PR **没有**调用 GDScript、提供 FFI 或转换 `formal_world_simulation_v15` 存档。

死亡不能只改本组件而不通知世界。建议宿主在候选世界上依次推进时间、调用本模块、将返回的 `DeathNotice` 应用于原人口/身份/劳动域，全部成功后再采用候选世界。失败时保留原世界及原时钟。本模块的单组件原子性不能替代跨域事务；死亡不自动没收资产、取消债务或完成继承。每次死亡通知仅返回一次，采用通知前不得独立保存本组件。登记前由宿主确认人物仍存活；恢复时还须核对整个世界中的存活标志与本模块一致。涉及死亡、工作和消费反馈的正式世界按日共同推进；多日批量仅用于历史条件已经确定的区间。

`ActionAssessment.ready` 仅表示查询当时必要条件满足，**不是**可重复使用的授权票据，也没有执行开厂、付款或招聘。真实动作必须在原领域执行处重新校验并预留/消耗资源。若迁移后的任务裁决需要概率，可在满足条件后使用它的统一随机源；本版能力输出是确定性的情境表现，不把所有社会结果压成一枚成功骰子。

## 范围与资源上限

每个实例最多 10,000 名具名人物；每人最多 128 个能力领域、128 条经历摘要和 128 种永久伤情。到达上限返回错误，不悄悄丢失经历。一个推进调用最多跨 366 日；更长时间由宿主分段。每次真正跨日会复制具名状态作为失败回退候选，工作量为具名人数 × 天数；不声称已测得万人规模性能。保存 JSON 最大 32 MiB。只读显示不复制整个世界。

尚未实现：Rust 正式宿主接线、游戏 UI、旧 Godot 存档转换、关系网络演化、遗产继承、疾病并发、完整就业/工厂行动执行和历史参数校准。不会修改现有经济算法、军事逻辑或输出 EXE/APK。

本地使用 Rust 1.100.0：15 项局部测试通过，可运行示例执行成功。测试覆盖资源/许可先行、未知条件、知识实践差异、公开视图、伤病与恢复上限、儿童和老年衰老、死亡及冻结行为、批量/逐日/保存恢复一致性、学习封顶、正负经历、事件去重、失败回退和非法存档拒绝。完整游戏实机与现有 Godot 全量回归未运行；现有 CI 未新增 Rust 检查流程，不将其原有 Godot 检查当作 Rust 验证。
